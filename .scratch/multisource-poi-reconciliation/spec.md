# 多源 POI 清洗与独立验证

## 目标

在不改变当前百度单源运行时的前提下，建立可审计的百度/高德 POI 候选对齐策略，并为后续独立人工验证保留最小必要证据。

## 验收范围

- 策略文档明确来源登记、坐标系、候选匹配、冲突处理、时效性、来源优先级和启用门槛。
- `reconcile_facilities()` 作为默认关闭的纯计算模块，不被当前分析主链路调用。
- 审计 fixture 只在取得书面许可、完成真实双源采集和 50–100 对人工标签后进入 `ready` 状态。
- 评估结果必须报告匹配 precision、recall、F1、冲突识别召回率、待复核率和混淆矩阵。
- 对外材料明确当前仍为百度单源，不把同源 64/64 宣传为多源准确率。

## 当前边界

高德 Web 服务 Key 和关于交叉验证、特征留存及公开展示的书面许可尚未具备，因此仓库只保存策略、来源登记、空的受控 fixture、离线规则测试和评估器，不伪造高德样本，也不启用运行时多源能力。
