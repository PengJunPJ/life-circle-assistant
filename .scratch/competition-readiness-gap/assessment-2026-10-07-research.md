## 可以优化但非核心功能阻断

1. **强化浏览器级验收**：给演示链路增加 Playwright 等真实浏览器测试，检查 JS 执行、地图可见、真实/离线 API 联调、图层交互和导出。当前 HTTP 冒烟仍不能替代视觉与交互验收。
2. **修复依赖安全风险**：官方 npm registry 审计确认 ECharts `<6.1.0` 的 XSS 风险、`source-map-js` 的高危拒绝服务风险，以及 Vitest/@vitest/mocker/Tinypool 的测试工具风险。ECharts 和 Vitest 的自动建议均涉及主版本升级，应单独开升级任务并执行完整回归，不能直接 `npm audit fix --force`。
3. **统一依赖与锁文件**：前端流程只使用 npm，但仓库同时保留 `package-lock.json` 和 `pnpm-lock.yaml`；应确认唯一包管理器后删除另一套锁。后端也没有完整传递依赖哈希锁。
4. **后端生产镜像最小化**：后端镜像仍复制 `tests`，运行依赖中包含 pytest，并以 root 启动。可拆分 runtime/dev 依赖、移除测试文件并使用非 root 用户。
5. **API 权限与限流**：CORS 和宿主绑定已收紧，但 API 仍无账号鉴权或业务级速率限制。比赛本地演示可接受；若部署到公共网络，必须增加反向代理、认证、限流与审计。
6. **更新性能基线**：`docs/performance/v2-baseline.md` 的历史数字不是在当前 release SHA 上采集；重新采集时记录 commit、机器/OS、依赖、QPS、缓存初态和原始日志，避免旧基线被误读为当前版本性能保证。
7. **清理 Python 测试告警**：当前测试仍出现 requests/urllib3 版本兼容告警和 `pytest-asyncio` 默认 fixture loop scope 弃用告警；补齐隔离环境和 pytest 配置，保持评审日志干净。
8. **核查百度地图数据再分发条款**：真实报告和 `walking_cache_seed.json` 含百度服务返回的派生内容。应确认适用 API 条款允许将路线/POI 数据随公开源码再分发；若不确定，改用合成演示 fixture，真实材料仅保留必要的脱敏汇总/受控证据。
9. **固定前端运行时版本**：本次 `npm ci` 在 Node `22.17.0` 下成功，但 `abbrev@5.0.0`、`nopt@10.0.1` 声明要求 Node `22.22.2` 或更高的兼容版本并产生 `EBADENGINE` 告警。应在 README/CI/Docker 中统一受支持的 Node 版本，避免评审环境安装结果漂移。

## 结论

按赛题文本，15 分钟等时圈/设施盲区、POI 与路径规划、开源许可证、Docker 演示、自动化测试、示例数据和技术设计文档均已具备；核心功能可以演示，当前工作树质量门禁通过。但地图基础能力中的“坐标转换”尚无实现证据，是提交前优先补齐或向赛方确认的硬要求风险。其余风险主要是证据与交付闭环：未提交工作树、密钥/数据打包审查、托管 CI 实际运行证据、截图/视频和赛事平台提交。准确率方面已有一个完整但同源的沙涌社区核查，不能超出其证据边界对外宣传。
