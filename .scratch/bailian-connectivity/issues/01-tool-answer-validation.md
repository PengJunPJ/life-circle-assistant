# 百炼模型工具执行成功后，最终回答格式与摘要数量触发规划助手降级

Status: resolved

## 问题

使用 `.env` 配置的 `qwen3.7-flash` 和项目现有 `OpenAICompatibleProvider`，原生工具调用能够执行，但规划助手最终回答未通过 `_validate_answer`，返回 `tool_rules_degraded`。

## 复现与证据

2026-10-13 使用合成报告连续测试两次，工具均执行成功，完整流程均降级。复测捕获的最终回复以 Markdown JSON 代码块包裹，摘要包含“匹配到一处菜市场设施”。

1. `planning_assistant._validate_answer` 直接执行 `json.loads`，代码块导致 `JSONDecodeError`。
2. 仅去掉代码块仍失败，摘要正则禁止“一处”等数量表述。
3. 纯 JSON 且摘要仅保留定性表述时，原证据引用可通过校验。

完整测试记录见 [联通与能力测试](../validation.md)。

## 影响

百炼鉴权、模型文本与 JSON 请求、原生工具调用本身正常，但规划助手不能稳定维持 `llm_tools` 模式。用户会看到降级提示，实际完成的工具结果仍保留。

## 后续评估方向

评估工具模式的最终 JSON 输出约束、代码块兼容方式，以及摘要违规后的纠正策略。应保留现有证据引用校验和“数值由工具展示”的约束。
