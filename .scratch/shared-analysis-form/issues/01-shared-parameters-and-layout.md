# 共用参数与左侧信息层级

Status: ready-for-human
Type: task

## 问题

自然语言预览与手工表单各自保存一套参数，入口与启动操作重复；标题、状态和低频输入挤占首屏；体检范围和地图显示缺少固定的职责区分。

## 实现

两个入口填同一套公共参数；收起低频设置、固定启动摘要与按钮，将地图展示控制移入地图工具栏。沿用已授权的按需体检及补充体检逻辑。

## 验证

- 默认自主设置；切换保留输入，一句话只填公共参数，地址歧义在同一位置区确认。未确认位置、未填入的描述、地图选点中、无效时间和空设施选择均禁止误启动。
- 固定底部摘要与唯一启动按钮；坐标、坐标系和精度折叠，状态详情折叠，快照范围与异常保持可见。
- 地图图层菜单独立控制设施和区域显示，未体检类别禁用。补充入口仅准备参数，同一按钮确认启动；失败保留原报告，修改下一次参数不改现有地图报告的时间。
- 前端 25 个测试文件、94 项测试全部通过；类型检查、静态检查、生产构建和差异空白检查通过。生产构建保留原有图表分块大小提示。
- 使用拦截接口的样例数据检查 1440×900 深浅主题、390×844 深浅主题及 320×568 窄屏：默认桌面首屏完整展示时间、七类设施、高级设置和启动按钮；底栏固定，无横向溢出；地图菜单避开底部导航。验证入口保留、共享参数、地图选点、未体检限制、补充失败与重试。
- 浏览器验证脚本与截图保存在 `/tmp/shared-analysis-form.IVZrtc/`，未调用真实分析服务。
