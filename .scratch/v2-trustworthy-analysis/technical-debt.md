# V2 后续技术债

## 报告契约的强类型化

当前 V2 报告已经通过固定的 `schema_version`、契约构造函数和公开 API 测试保护，但后端分析、导出、比较与模拟模块仍广泛使用 `dict[str, Any]` 传递报告章节。最终审查确认，直接在交付收口阶段把完整报告替换为 Pydantic 模型或多层 `TypedDict` 会同时扰动持久化、导出和历史报告兼容路径，风险高于收益，因此本次不改动稳定的 JSON 契约。

后续应单独立项，按“质量事件与执行阶段 → 服务区域 → 评分与建议 → 顶层报告”的顺序渐进引入强类型，并为旧版持久化报告保留兼容解析测试；完成前不得改变 V2 的公开字段和枚举语义。
