# 06：增加步行计算缓存与可靠降级

**要构建的内容：** 优化真实地图模式下的大量步行计算，使系统能够复用有效结果、控制并发和限流，并在部分请求失败时生成明确标注的不完整报告，而不是使整次体检不可用。

**阻塞于：** 04：按设施类别识别服务盲区

Status: ready-for-human

- [ ] 步行计算优先采用批量距离能力，无法使用时采用配置化的受控并发。
- [ ] 相同起点、终点和出行方式的有效结果可以从缓存复用。
- [ ] 缓存记录数据来源、创建时间和有效期，过期结果不会被当作有效缓存使用。
- [ ] 地图请求具备超时、有限次数重试、退避和限流错误识别。
- [ ] 单个类别或部分网格计算失败时可以生成部分报告，并明确列出失败范围。
- [ ] 失败类别不会被纳入有效综合评分。
- [ ] 报告显示 API 调用量、缓存命中量、降级使用情况和实际分析耗时。
- [ ] 自动化测试覆盖缓存命中、未命中、过期、超时、限流、格式错误和部分失败。
