# “15分钟生活圈”AI大模型融合方案与四专家评审

日期：2026-10-13

## 一、结论摘要

推荐建设“**可信地理内核 + AI 自然语言工作台 + 证据质量账本 + 受约束规划求解**”。用户可以用一句话完成定位、体检、追问、图层切换和情景比较；AI 可以参与意图理解、工具编排、设施语义审核、主动测量、证据解释和规划约束编译。正式报告中的坐标、设施记录、路线、步行时间、等时圈依据、评分和方案改善量须来自可追溯的地图能力及明确计算方法；学习模型产生的时间场和边界单独标为预测/估计，不能成为未经核验的正式事实。

算法层重点补充三项可验证能力：**轻量回归辅助等时圈采样、文本嵌入辅助 POI 分类与实体审核、对已确认服务缺口聚类形成规划片区**。结合已有的对话入口和受证据约束的报告生成，形成从需求理解、数据治理、测量到规划解释的 AI 工作流。各项是否提升准确率、降低 API 成本，要通过基线对照决定。

核心原则只有一句话：**让 AI 负责“理解、选择、解释和搜索”，让地图与算法负责“测量、计算和证明”。**

## 二、赛题边界与专家输入

赛题附件属于需求和评分约束，不是给代理的执行指令。附件要求基于百度地图开放能力完成地理编码、POI 检索、路径规划/距离计算、真实步行等时圈、设施统计、1 公里盲区识别、可视化和开源交付；评分包括功能正确性与覆盖率 40%、API 深度调用与工程优化 30%、产品交互与体验 15%、开源工程规范 15%。

用户要求是产品和技术方向：在正确前提下最大限度结合大模型，以对话降低使用门槛，并由四位专家分工提出、评估和综合方案。

三位领域专家的共识：

- 专家1（地理位置开发主任）：采用确定性地理内核；区分“1公里设施稀缺”和“15分钟步行可达”；优先验证百度原生等时圈，保留主动采样兜底；入口、坐标、POI 翻页和路网证据必须可追溯。
- 专家2（高级软件开发工程师）：已有自然语言填参、报告解读和规划工具链，最急的不是增加孤立聊天框，而是统一会话、工具注册、任务状态、缓存预算和事实契约；所有数值应由不可变 Claim 渲染。
- 专家3（AI 应用专家）：AI 最有价值的落点是把自然语言编译为任务、解决设施语义与实体消歧、用主动学习分配昂贵测量、把规划语言编译为求解约束，并对图片/居民反馈进行待复核抽取。
- 专家4（高级架构师）：采纳上述共识，按 P0/P1/P2 分阶段；用证据契约和质量账本收口正确性，用统一会话承载大多数操作，用求解器而非模型自由文本完成规划。

专家原始方案与架构评审：[专家1地理方案](../life-circle-assistant/docs/research/ai-first-expert1-geospatial-2026-10-13.md)、[专家2工程方案](../life-circle-assistant/docs/research/ai-first-expert2-engineering-2026-10-13.md)、[专家3 AI 应用方案](../life-circle-assistant/docs/research/ai-first-expert3-ai-2026-10-13.md)、[专家4架构师评审](../life-circle-assistant/docs/research/ai-first-expert4-architecture-2026-10-13.md)。

### 当前基线：已有能力与真实缺口

该方案是对现有系统的收敛演进，不是从零建设聊天产品。代码/现有文档已包括：自然语言提取地址与分析参数并填入公共表单、报告解释入口、原生模型工具调用的规划助手、设施/网格证据查询、单设施情景模拟、2–3 个独立方案比较、SQLite 报告与问答存储、百度真实/快照/Mock 路径、4×4 网格服务区域和径向采样/二分边界细化。高德多源核验模块是默认关闭的观察旁路，不能称为主流程融合。

关键缺口和风险不是“没有 AI”，而是现有能力分散且校验强度不一致：

- `NaturalLanguageAnalysis.vue` 当前主要是“一句话填公共表单”，还不是能恢复的多轮对话工作区；报告解读与规划助手也有独立交互状态。
- 专家2用离线 FakeProvider 复现：真实报告分数为 68 时，模型可在引用合法报告 ID 的情况下返回“总分99、药店步行1分钟”，普通 `/ai/interpret` 仍接纳了这些错误数值。该结果证明引用 ID 合法不代表结论受引用支持；它是离线复现的校验缺口，不应夸大成每次线上调用均已出错。应在新增 AI 数值回答前将其列为 P0 门禁。
- `recover_interrupted()` 将中断任务标为失败，并非断点续跑；浏览器 `AbortController` 丢弃响应也不代表后端已停止地图/模型请求或费用。
- 当前百度步行矩阵适配器批次常量为 100；百度官方公开步行/骑行单次路线对上限为 50，且配额按路线对而不是 HTTP 请求计。建议按 50 实施安全分块，账户级配额、QPS、计费和接口响应仍须单独核验。矩阵 `0` 可能承载“无结果”，需要区分合法同点零值、无解和响应缺失。
- 当前 POI 检索每个关键词取第一页，不能把检索结果称为完整名录；超出范围、分页未完或路线失败要保持未知/部分结果。
- 当前服务盲区结果有四态和 `lacks_nearby_facility` 字段，但赛题的 1 公里稀缺要作为独立统计/图层呈现；保留现有分类语义，补足可读性，不把“无近邻但仍可达”误报为重点路网盲区。
- 代码采用 16/24 方向、最高 1,250 米的采样及二分细化；同射线时间单调、边界孔洞/断片和真实入口等均有边界。百度官方等时圈服务文档存在不代表当前项目已获得账号权限或已集成。

上述状态以报告日期仓库为基线；详见[工程专家的实现盘点](../life-circle-assistant/docs/research/ai-first-expert2-engineering-2026-10-13.md)和[地理专家的 API/算法核对](../life-circle-assistant/docs/research/ai-first-expert1-geospatial-2026-10-13.md)。

## 三、最优总体架构

```text
自然语言/地图操作
       ↓
ConversationService：会话、澄清、确认、历史、取消、幂等
       ↓
AI Orchestrator：意图、工具计划、语义审核、主动测量、解释
       ↓
CommandRegistry：白名单工具、结构化参数、权限和预算校验
       ↓
JobService ─ Evidence/Claim Store ─ Quality Ledger
       ↓                         ↓
地图适配器/缓存/限流          证据问答/报告/导出
       ↓
可选 AI 分析旁路：POI 语义候选、回归预测与采样调度、已确认缺口分组
       ↓ 仅通过校验的数据或追加测量进入正式计算
确定性地理内核：地理编码、POI、步行矩阵/路线、等时圈、分类、评分
       ↓
Planning Solver：候选生成、精算、情景复算、帕累托比较
```

### 1. AI 可以做什么

1. 将“帮我看看这个社区”“改成20分钟”“东南角为什么不方便”转成带来源和置信状态的结构化任务。
2. 选择下一批最有信息量的测量点：阈值附近、道路/河流等障碍两侧、预测分歧大和规划候选点。
3. 判断 POI 类别、别名、父子实体和同名候选，低置信度交给人工复核。
4. 从 Claim 和规范文档生成面向居民、社区工作人员或规划人员的不同解释。
5. 将预算、最多新增数量、候选地块和优先短板编译为求解器约束，并解释有限模型内的方案差异。
6. 抽取居民图片和留言中的“疑似关闭、入口变更、临时围挡”等观察，形成待核验事件。
7. 用轻量回归模型估计步行时间场和不确定区域，辅助选择下一批 API 测量；以独立估计图层展示学习结果。
8. 将已确认的同类别服务缺口分组为可解释的规划片区，供候选生成与复算；保留逐网格判定证据。

### 2. AI 不能做什么

LLM 不能自行写经纬度、制造路线/时间/设施、凭空生成等时圈多边形、修改评分、把估算称为实测、把 POI 缺失称为全域不存在、把可行解称为现实审批结果，或用图片和第二地图源未经核验地改写正式报告。回归和聚类的结构化输出须按方法、来源与质量标记呈现，不能绕过上述事实边界。

## 四、核心正确性设计

### 1. 两个指标分开

每个网格和设施类别同时保存：

- `nearby_count`：1公里空间范围内设施数，表达设施稀缺；
- `reachable_time`：从网格代表起点到设施可服务入口的最短成功步行时间，表达路网可达。当前代表起点为格中心；入口缺失时回退设施点并记录假设，不能把此结果表述为每户居民到真实入口的时间。

报告分别展示“设施稀缺区”“步行超时区”和“稀缺且超时的重点服务盲区”。现有 `normal/sparse/critical/unknown` 四态分类继续兼容，但不能把“1公里内没有设施但15分钟可达”误称为重点盲区。

### 2. 证据 Claim

每项事实采用不可变结构（以下仅为契约示例，不是真实路线结果）：

```json
{
  "claim_id": "claim-...",
  "subject_id": "cell-...",
  "predicate": "nearest_walk_minutes",
  "value": 12.4,
  "unit": "minute",
  "origin": "baidu_api",
  "method": "walking_matrix",
  "report_version": "...",
  "computed_at": "...",
  "quality": "high",
  "evidence_refs": ["route-...", "poi-..."]
}
```

模型只提交 Claim ID、工具参数或定性解释；服务端检查报告版本、对象范围、单位和引用合法性，最后由渲染器填充数值。无证据、过期、跨报告或未知 Claim 必须拒答、追问或显示“无法判定”。

### 3. 地理质量账本

每个任务记录真实 API、缓存、模拟、插值、失败、重试、POI 翻页截断、入口假设、坐标转换和采集时间。对外 GeoJSON 按 RFC 7946 使用 WGS84；内部百度计算可保留 BD-09，但必须显式标注坐标系和经纬度顺序。

## 五、AI 解决传统地理计算难题的落地路径

### 阶段 P0：正确性门禁 + 可信对话工作台

优先把普通 `/ai/interpret` 与规划助手统一纳入 `Evidence/FactClaim` 校验，确保模型无法自由输出未证实的分数、分钟或改善量。然后统一 `resolve_location`、`search_facilities`、`measure_routes`、`get_isochrone`、`inspect_cell`、`simulate_facility`、`compare_scenarios` 等白名单命令，复用现有分析和规划能力。自然语言参数提取和规划工具不是从头开发；增量是统一会话状态、地图上下文、任务历史、revision、进度和事实出口。先展示任务参数、请求/费用档位与质量提示，再执行会产生外部调用的任务。

地理内核同步修正：步行矩阵默认按公开 50 条路线对分块；POI 翻页并启用严格半径；保存 `uid`、`navi_location`、入口来源；把真实、缓存、模拟和估算结果分开；把设施稀缺状态独立成层。

### 阶段 P1：语义审核与主动测量

先用规则和空间条件生成 POI 候选，文本嵌入模型辅助类别匹配与同实体候选召回，大模型处理歧义并提供原字段引用，低置信度进入复核；不自动创建坐标或覆盖主数据。类别归一化与实体去重分别执行，不能因“药店/药房”语义相似就合并不同门店。

等时圈先探测百度原生 `foot_fastest`/`foot_shortest` 权限、计费和返回几何；账号不可用或需细化时，使用“主动采样”：不让 LLM 自由编点或路线，而由采样策略按预算/不确定度选测量点，真实 API 负责测量，阈值附近和高风险点必须精算。输出 API 观测边界、估计边界和未决带，不能把插值冒充路网事实。与固定采样基线按同等错误水平比较请求数、误判可达率和未决覆盖后，再决定是否启用。

回归预测作为主动采样的可选支撑；先验证是否比规则加密和传统插值有收益，再决定是否承担模型训练、校准和部署成本。服务区域正式分类完成后，再对同类缺口进行相邻连通分组或 DBSCAN 分组，帮助识别需要整体改善的片区；分组不能替换赛题稀缺与可达性口径。

### 阶段 P2：约束规划与反馈闭环

用户说“只考虑三个地块、最多增加一个药店、优先解决现有盲区”时，模型编译约束，求解器计算有限候选集合。每个方案独立复算并展示 `before/after/delta`、硬约束、求解状态和 API 成本。人口、容量、土地合法性缺失时，只能称空间覆盖改善。

居民图片/留言只形成待复核观察；确认前不改变正式 POI、路线和报告。

## 六、具体 AI 方法与架构师取舍

### 1. 机器学习插值：学习步行时间场，辅助补测

将真实成功路线样本组织为 `(起点、目标点、提供方步行秒数、入口来源、采集时间、质量)`，学习直线空间位置与步行时间之间的局部非线性关系。失败、零值语义不明和过期结果不作为“不可达”或零分钟标签。API 时间是提供方估计标签，独立现场计时另存，不能将两者混称实测。

候选特征包括相对中心点的米制位移、直线距离、方向、邻域已测时间及其变化、已知屏障和入口信息。路网密度、道路等级、河流/铁路等特征仅在拥有明确来源、许可和可用数据时接入；没有路网数据时不把这些写成现有输入。未知点的路线时间、绕行率不能反过来作为该点预测特征，避免用答案预测答案。

| 候选方法 | 本项目的用途与启用条件 |
|---|---|
| 高斯过程回归（GPR） | 优先用于小范围、有限样本试验，预测均值与模型标准差，辅助阈值附近补测；标准差不自动成为可靠地理误差界，须校准并检查障碍两侧表现。 |
| 随机森林 / 梯度提升 / XGBoost | 在有足够独立路线标签、特征可复用时做对照；预测区间需要额外校准，不能把树模型单点预测当确定分钟数。 |
| 小型 MLP | 数据量与跨社区验证证明有收益后再评估；当前少量扇形样本不支持默认采用神经网络。 |
| 图神经网络（GNN） | 需要有许可的步行路网拓扑、节点/边特征和训练标签；当前不能取得完整路网时，不作为主方案，也不承诺能替代百度路线服务。 |

执行流程：初始 API 采样 → 局部模型拟合与校准 → 预测时间场/不确定区域 → 选取下一批路线对 → API 回填 → 迭代停止或保留未决带。河流、围墙、封闭园区可能造成不连续，不能为了“平滑好看”填满未知区或跨障碍连接边界。低置信、接近 15 分钟阈值、重点盲区和最终规划候选仍需精算。

验收同时看两件事：时间预测误差，以及误判可达率、阈值附近混淆矩阵和未决比例。用空间分块/留出社区隔离训练与评估，局部模型留出独立点用于校准；同一缓存路线不能重复计为独立样本。与当前径向采样、等预算均匀采样、反距离加权等传统插值、规则主动加密做对照，必要时加入克里金基线。只有在同误差下路线对数下降，或同预算下关键判定改善时，才把模型纳入默认策略；否则保留基线。

### 2. NLP 设施治理：语义分类与实体去重分开

文本嵌入模型可选 Sentence-BERT、经许可证核查的中文 text2vec 或其他中文嵌入模型，用于对名称、地址、类别和机构说明编码，召回相似类别或疑似同实体。只对这些候选调用 LLM 做结构化裁决，减少逐条模型调用和费用。

- **类别归一化**：“药店/药房”“菜市场/农贸市场”可映射到同一标准类别；“生鲜超市”是否满足菜市场服务口径，要依据类别规范和服务属性判定。扩展“买菜便利”分析可采用另一有标记的服务分类，不能静默修改赛事类别和评分。
- **实体去重**：语义相似仅提供候选，不证明同一门店。须结合统一坐标后的距离、地址、UID、父子机构、分店/校区/入口关系；“华润万家”和“万家超市”不能只凭名称自动合并。
- **疑难分类**：零样本大模型输出候选类别、原始字段短引、冲突与未知原因；自报置信度未经校准不能当正确概率。未达到审核阈值的候选保留原记录并进入人工复核。

形成流水线：规则标准化与空间筛选 → 嵌入召回 → 歧义项 LLM 裁决 → 规则/来源校验 → 接纳或人工复核 → 版本化设施目录。保持主体、内部科室、校门和导航入口的层级，避免重复计数或删除有效分店。用同品牌异店、同名异地、医院科室、多校区和迁址样本评估类别准确率、错误合并率、漏合并率及复核工作量；在结果出来前只称“语义辅助治理”，不称覆盖统计已经更准。

### 3. DBSCAN：把已确认缺口组织成规划片区

对所有 POI 做 DBSCAN 可展示设施聚集形态，但聚类间的空隙或噪声点不能证明那里缺少服务。没有 POI 的水域、厂区或空地不一定有居民需求，近处没有点也可能经路网在 15 分钟内到达设施。

推荐把聚类用于**正式计算之后**：按设施类别选出已确认稀缺、步行超时或双条件重点盲区的网格，分开形成缺口簇；未知网格保持独立，不作为缺口样本。当前只有 4×4 网格时先用相邻格连通分组，分辨率足够后再试 DBSCAN，以米制距离选择 `eps`、明确 `min_samples`、检查参数敏感性，并保留孤立但确有证据的缺口格。

片区几何由成员网格的并集生成；不把正常/未知网格或河道填进簇的凸包。河流两岸、铁路两侧和不可互通小区即使空间相近，也要结合已验证障碍/入口或步行邻接条件限制分组。每个簇保存成员网格、类别、缺口证据、最不利时间、缺失比例和方法版本，再交给候选生成模块提出补点范围。它辅助描述与规划，不改变成员网格原本的判定或评分。

若接入有授权、时效和粒度明确的人口/需求数据，可把“片区内未覆盖需求”作为排序权重；没有这些数据就仅报告空间缺口，不能从普通热力图直接换算受益居民数。KMeans 可用于其他探索性分组，其强制分簇不能代替稀缺/可达判断。

### 4. LLM 报告：解释经过证明的观察与方案

AI 报告分别输出观察事实、可能原因、拟议措施和待核验条件，适配居民/社区工作人员/规划人员的表达。事实数值、点位和变化从 Claim 槽位装配，例如：

> “当前检索发现 {设施数 Claim} 家药店；你选中网格到最近成功匹配药店的地图步行估计为 {时间 Claim}，与本次阈值的关系为 {判定 Claim}。候选 A 新增药店情景的变化见 {复算结果 Claim}；入口、营业与建设条件仍需核验。”

每项 Claim 必须绑定同一报告口径、起点、单位和来源，计数说明是否属于完整检索窗口。若没有人口、面积/路线证据或可信候选，LLM 不补写“某片区居民需18分钟”“改善0.3平方公里”“建议在某路口建设”等事实。因果解释标为假设；正式推荐的候选和优先级由复算/求解器产生，LLM 负责说明取舍。

### 5. 设施选址：先求解最大覆盖，再考虑更重的方法

将已核验缺口分组、可信候选位置和步行可达矩阵组合成最大覆盖问题：在预算/数量约束下选择设施，使已定义的未覆盖需求或网格改善尽可能多。小规模候选优先用穷举验证、确定性贪心作基线，再用 CP-SAT/MIP 处理组合约束；贪心不自动称最优，精确求解也只针对给定候选和数据模型。

遗传算法、模拟退火可在搜索规模/约束复杂到需要启发式时做对照，公布随机种子、运行预算、约束违规、目标差距和重算一致性。强化学习需稳定环境、奖励定义和足够训练/评估数据，当前不列为近期主线；“使用强化学习”本身不证明选址更优。

### 6. 最小可交付组合与竞赛叙事

最小组合是**复用现有自然语言和报告能力 + 统一 Claim 门禁 + 一项经过独立验证的语义分类/去重增量**。可视化缺口分组有助于演示，但不把“调用一次模型 + 加一段聚类代码”视为完成 AI 方案，也不按“不到200行”估算数据审核、异常处理与评估成本。进一步以主动采样同预算/同误差对照作为空间算法创新证据。

建议项目定位使用以下表述：

> 本项目是以自然语言为入口、以百度地图路网证据为基础的 AI 城市生活圈体检与规划助手。大模型把居民需求编译成受控任务，语义模型辅助设施治理，学习模型在经过验证的场景下辅助分配地图测量预算；系统基于真实路线判定服务缺口，以缺口分组和约束求解组织规划候选，并用可追溯事实生成解释与报告。

“创新的空间插值”与“多源清洗”给这些方法提供应用空间；算法是否有用以专项指标与真实测试为依据。不将“开源 AI 工具赛道”直接推导为评审要求某种模型，不揣测命题方必然期待 GNN/强化学习，也不宣称机器学习天然比传统插值或固定口径更准确。实施状态、实验结果和路线图应分别披露。

## 七、赛事演示建议

演示一句话：

> “以黄埔区这个社区为中心，按15分钟常规步行，检查菜市场、药店、小学和医疗服务；分别告诉我一公里内稀缺但仍可达的区域和真正重点盲区，再比较两个候选位置新增药店后的变化。”

系统应完成：位置候选确认 → API/缓存预算预览 → 真实地图体检 → 稀缺/可达/重点盲区分层 → Claim 证据解释 → 两个候选点情景复算 → 连续追问和导出。该路径同时体现 AI 交互、百度 API 深度调用、传统空间计算和可解释规划。

## 八、实施优先级与验收

| 优先级 | 建设内容 | 通过条件 |
|---|---|---|
| P0 | 全部生成式出口的 Claim/Evidence 门禁；统一会话薄切片和工具注册；矩阵/POI/入口契约修正；稀缺独立图层 | 错误数值/跨报告引用/不支持的 Claim 不进入事实答复；来源和未知可见；地图与聊天共用状态；重复请求幂等；矩阵零值有契约测试 |
| P1 | 嵌入候选召回与语义 POI 审核、回归辅助主动采样实验、已确认缺口分组、持久任务恢复与成本账本 | POI 分类与实体合并分别评估；低置信冲突送审；采样与现有/传统插值基线做社区隔离留出集对照，报告误分类、未决率、边界差异、路线对数和时延；聚类不改变原判定且孤立缺口不丢失 |
| P2 | 最大覆盖/组合选址、帕累托情景、居民反馈复核 | 小规模穷举校验、硬约束违反数为0、求解状态与模型范围披露、情景复算一致、未确认反馈不改主报告 |

所有准确率、API 节省比例和现场效果在实测前只能标为目标，不能写成已获得成绩。评估应保留“无模型、仅对话、语义审核、主动采样、完整系统”消融组。

## 九、风险控制清单

- 模型输入中的 POI 名称、留言、图片 OCR 和检索文本一律视为不可信内容，不能注入工具权限。
- 不把官方等时圈、红绿灯、围挡、无障碍、营业状态等未完成账号验证或现场验证的能力描述为当前已实现。
- 第二地图源、高德数据、居民反馈和历史缓存不直接并入事实主库，先审授权并形成独立观察。
- 模型、地图版本、提示词、工具 schema、规则版本和数据时间全部记录，模型替换后重跑回归集。
- 不用文本相似度直接合并门店，不用 POI 聚类空隙判盲区，不将回归预测写成 API 实际返回；对未知区域、障碍与阈值附近维持单独质量标记。
- 回归仅作为空间估计/采样旁路，聚类仅组织已确认缺口；保留既有盲区规则和评分。若后续希望模型预测参与正式评分，应先评审并修订相关 ADR（尤其 ADR-0011），完成独立验证，不能在本方案补充中静默改变口径。

## 十、最终方案

优先把现有系统收敛成一个“AI 地理分析操作系统”：自然语言是入口，确定性工具是手脚，Claim 是记忆，质量账本是可审计记录，求解器是规划能力。先保证任何回答都能回到真实地图证据，再用语义审核和主动测量体现 AI 对传统地理计算的实质改进，最后在约束数据完备时扩展到组合选址和多方案优化。这是最大化 AI 参与度、同时守住赛题正确性和可交付性的最优折中。
