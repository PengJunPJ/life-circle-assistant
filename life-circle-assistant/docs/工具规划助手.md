# 可调用工具的规划助手

## 使用方法

先完成一次体检或打开已完成的历史报告。在右侧“可解释 AI 规划助手”输入问题，点击“提问”。例如：

- “查一下菜市场盲区，再模拟新增一个菜市场。”
- “查询药店，解释这些网格为什么被判为服务盲区。”
- 模拟后追问：“为什么这里值得优先考虑？有哪些证据还需要核验？”

“查询服务短板”“候选设施模拟”和“比较方案”提供快捷入口。多方案比较可先选择目标；可选择减少重点盲区、扩大分类覆盖或提高综合指数。每次问答完成后显示实际执行的工具、参数、结果、耗时、失败原因和来源。查询只覆盖当前报告已经分析的设施类别；设施步行时间从分析中心出发，网格证据从网格中心出发，两者不能混用。

点击地图网格可以给助手带入该网格。要指定新增设施位置，在“新增设施改善模拟”选择类别、点击“地图选点”，选点后再提出“模拟新增菜市场，使用我已选择的地图点”。助手只接受报告中的候选点标识或用户当前地图选点，不接受模型生成的坐标。用户选点须处于黄埔区支持范围，且距当前中心不超过两公里。

没有位置时，模型应请求补充；规则模式有明确类别和报告候选点时使用返回的首个候选点，没有可用候选点则提示补充。候选点只是报告提出的待核验位置，不代表已获用地许可或适宜建设。

模拟成功后直接显示现有地图的假设设施和模拟区域，并在“新增设施改善模拟”展示前后指标；“在地图查看本次模拟”可重新显示保存的结果。查询、模拟失败时不会生成成功模拟事件。原始报告、评分和设施主数据保持不变。

追问会引用当前报告的服务端历史问答；“开始新话题”清空关联，切换报告隔离上下文与过期响应。页面目前展示最新问答结果，完整记录保存在报告解读历史中，JSON 导出包含工具执行记录和模拟数据。

## 模型配置与降级

在应用目录 `.env` 设置现有的 `LLM_ENABLED`、`LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，然后重启后端或重建容器。自然语言体检、报告解读和工具助手共享这组配置。

工具助手要求兼容 Chat Completions 的原生 `tools` / `assistant.tool_calls` / `role=tool` 协议。仅能返回文本的服务不足以完成原生工具循环；实际支持情况须以所选服务和模型的连通性测试为准。问答会向外部服务发送问题、报告质量信息、已执行工具结果和上轮上下文；不会发送地图完整几何或应用密钥。

| 界面模式 | 实际行为 |
| --- | --- |
| 大模型 · 工具调用 | 模型选择函数，后端实际执行，并把结果返回模型继续处理 |
| 规则工具 · 模型未启用 | 根据关键词或上一轮类别选择同一组后端工具，不调用模型 |
| 规则工具 · 已降级 | 模型请求、证据校验或预算失败；保留实际完成的工具结果，失败不算有效证据 |

没有任何已尝试工具时，降级流程只在剩余时间内尝试规则工具；已执行过工具时不自动重跑，尤其不会重复模拟。模型异常详情不会直接显示给用户。

## 工具与计算边界

| 工具 | 输入与真实执行内容 |
| --- | --- |
| `query_facilities` | 按类别、名称或地址关键词过滤报告内已清洗设施；最多返回二十条，并显示匹配总量 |
| `get_grid_evidence` | 按类别、网格标识或判定类型查询报告证据；保留步行阈值、最近设施、来源与失败情况 |
| `get_planning_candidates` | 读取报告建议中的候选位置及标识；最多返回二十个候选点 |
| `simulate_facility` | 校验现有候选点或用户地图点，实际调用既有模拟服务复算类别评分、综合评分、覆盖与盲区变化 |
| `compare_planning_options` | 校验二至三个不同的类别/位置方案，逐个以原报告为基线执行模拟，再对完整可比的方案按指定目标排名 |

前三项查询来自已完成报告快照，不重新搜索实时设施。模拟使用当前地图提供方，真实模式可能调用路线接口及缓存；离线模式仍是本地合成数据，不能作为实测效果。部分路线失败会保留质量披露，不能把缺失证据说成服务达标。

每轮最多六次工具调用、五轮模型请求；单设施模拟或一批最多三个独立方案比较二选一，总预算九十秒。比较批次逐项使用同一原报告，不叠加方案。部分路线失败、unknown 网格、原报告不完整或目标指标缺失的方案不参与排名。并列保留，没有至少两个可比方案或目标改善值非正时不宣称优先方案。超时会保留已完成结果、标记未完成方案且不为其排名。比较目标、覆盖面积口径和成本/用地等未计算边界见[多方案比较](多方案比较.md)。模拟失败也计入本轮预算；下一轮才能重新提出请求。模型不能调用任意网络、命令、写入设施或删除报告。

服务端只接受成功工具结果或服务端上轮上下文中的证据引用；最近六份成功工具结果用于继续追问。模型最终解释限制为定性文字，评分、分钟、面积和改善量直接从工具原始结果展示。该约束能拒绝未核验数值和虚构引用，不能证明所有定性解释正确；选址仍需现场、入口、用地与居民需求复核。

最终回答兼容纯 JSON，以及完整的 `json` / `JSON` 或无语言标记的 Markdown 代码块；代码块前后附带说明、截断 JSON 和虚构证据仍会被拒绝。若证据合法但摘要含“一处”“两处”或阿拉伯数字等数量表述，会基于已有成功工具结果请求一次 JSON 模式的定性改写，再执行相同校验。改写计入五轮模型请求和九十秒总预算，不重新执行查询或模拟；改写仍不合格、失败或超预算时保留实际结果并降级。当前提示词版本为 `tool-planner-v2`，历史 `tool-planner-v1` 问答仍可继续追问。

## 接口与实现

`POST /api/reports/{report_id}/ai/plan`，请求示例：

```json
{
  "message": "查一下菜市场盲区，再模拟新增一个菜市场"
}
```

追问可传上轮响应 `id` 作为 `previous_turn_id`；地图点通过 `selected_location` 传 BD-09 经纬度，所选网格通过 `grid_id` 传入。客户端不能传入任意历史结果作为事实。报告不存在或未完成返回 404；非法参数、外部报告轮次、非法地图点或网格返回 422。

响应主要字段包括 `id`、`report_id`、`summary`、`mode`、`evidence_refs`、`tool_calls`、`simulations`、`comparisons`、`planning_context`、`data_quality_notice`。工具条目 `status=completed` 表示实际完成该次操作，`failed` 条目包含错误，不作为证据；降级也可能含有效模拟结果，请同时查看每条状态。

后端入口：`backend/app/planning_assistant.py`，原生协议适配器：`backend/app/llm.py`。问答存入既有报告解读表，无需新增数据库迁移。前端入口：`frontend/src/components/AiPlanningAssistant.vue`，结果列表：`PlanningToolResults.vue`，模拟联动复用 `useSimulation.ts`。
