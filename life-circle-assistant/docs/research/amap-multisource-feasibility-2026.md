# 高德地图作为第二 POI 来源的可行性评估

核对日期：2026-10-10（Asia/Shanghai）。

研究范围：高德开放平台公开的官方接口文档、配额说明及服务协议。未调用带用户凭据的真实接口，未创建账号/Key，未修改业务代码。下面明确区分官方事实、项目建议与尚待核实的权限。

## 结论

技术上可行，适合把高德 Web 服务作为百度 POI 结果的第二交叉观察源，先在一个社区、少数设施类别进行按需验证。高德提供文本、周边、多边形和 ID 搜索，以及地理/逆地理编码、坐标转换，足以支持类别映射、候选匹配和差异分析。[S1][S2][S3]

核心前置条件是取得适用的服务权限和确认数据使用范围。高德当前服务协议对存储、缓存、构建数据库、传播内容和算法训练有明确限制；普通 Key 或购买技术服务许可不能直接推导出离线快照、GitHub 再分发或融合数据库授权。开源竞赛、跨厂商验证、在百度底图显示高德结果和公开审计样例的具体用途，应通过工单取得明确答复。[S6]

高德与百度属于两个接口/数据提供方，但本次官方资料未证明两者底层采集完全独立。两源一致性只能衡量交叉观察结果，不等于独立真值或准确率。人工实地记录、官方设施名录等额外证据才能用于验证实体的存在、类别和开放状态。

## 官方接口事实

| 能力 | 核实结果 | 项目影响 |
|---|---|---|
| POI 搜索 | 支持文本、周边、多边形、ID 四种查询；V3 地址为 `place/text`、`place/around`、`place/polygon`、`place/detail`。[S1] | 首期采用周边查询，按设施类别配置关键词与类型码。 |
| POI 字段 | 文档列出 `id`、`name`、`type`、`typecode`、`address`、`location`、父 POI、入口坐标等字段；缺失值可能返回空数组。[S1] | 使用 `amap:<id>` 来源内标识；空数组须规范化，不能直接转字符串；父子 POI 需要区分。 |
| 完整性 | 官方明确搜索不支持返回全量数据，相同请求参数翻页最多 200 条；V3 每页 `offset` 强烈建议不超过 25。[S1] | 记录分页/截断状态，不能把未返回解释为不存在；不要通过网格分片规避限制建立全量库。 |
| 查询范围 | 文本查询 `city` 支持城市名、citycode、adcode，`citylimit` 限定指定城市；官方建议 adcode 以提高精度。周边查询使用 `location` 和 `radius`，与文本接口参数分别遵循各自表格。[S1] | 首期以同一真实中心点/半径查询，再做统一空间过滤；不要把 `citylimit` 机械应用于所有接口。 |
| 地理编码 | `GET https://restapi.amap.com/v3/geocode/geo`，将结构化地址解析为高德经纬度，结果含 `level` 匹配级别。[S2] | 可辅助复核地址；不是实体 ID，也不能把低级别地址解析直接当 POI 位置。 |
| 逆地理编码 | `GET https://restapi.amap.com/v3/geocode/regeo`；`location` 经度在前，`radius` 为 0–3000 米；`extensions=all` 可返回 POI/AOI/道路。[S2] | 用于按需地址复核，不能代替区域 POI 全量搜索。 |
| 坐标转换 | `GET https://restapi.amap.com/v3/assistant/coordinate/convert`，输入 `coordsys` 支持 `gps`、`mapbar`、`baidu`、`autonavi`，转为高德坐标；单次最多 40 对，输入以 `|` 分隔、输出以 `;` 分隔。[S3] | BD-09 查询中心可用 `coordsys=baidu` 转为高德输入。该接口不提供任意目标坐标系选项。 |
| Key | 需注册开发者、创建应用、为应用添加服务平台为“Web 服务”的 Key；请求中必填 Key。[S4] | 后端调用，不能用 JS Key 代替；Key 不进仓库/前端/审计日志。 |
| 配额 | 官方流量说明把调用配额指向定价页面，QPS 要在控制台“流量分析－配额管理”查看。[S5] | 不能在设计中写死一个未经账号确认的免费 QPS/每日调用数；需核实搜索权限及账号实际预算。 |
| 错误 | 响应 `status` 为 0/1；官方错误码覆盖 Key 不正确、服务无权限、日配额、IP 白名单、平台不匹配、QPS 超限等。[S1][S7] | HTTP 200 不等于成功；权限/参数错误立即失败，限流做有限退避，输出 partial/failed。 |

POI 搜索页面标注更新日期为 2026-07-15，坐标及地理编码页面为 2026-02-02，Key 文档为 2026-03-30。实施前应再次核对，因为官方契约和权限可能更新。[S1][S2][S3][S4]

## 坐标策略

项目当前统一使用 BD-09，已有百度 Geoconv V2 研究记录：GCJ-02 转 BD-09 使用 `model=1`，单次最多 100 点。高德输入/输出按高德坐标契约处理，不得把它直接当作 BD-09；高德转换接口中的 GPS、baidu、高德标签应分别与项目 WGS84、BD-09、GCJ-02 明确映射，实施时通过官方契约和真实请求验证。[S3][S8]

建议链路：项目 BD-09 中心点 -> 高德官方 `coordsys=baidu` 转换 -> 高德查询 -> 高德来源坐标保留 -> 百度 Geoconv V2 `model=1` 转 BD-09 -> 跨源距离计算。40 点限制只针对高德转换；反向百度转换遵循其 100 点限制。禁止把高德接口误写为可返回 BD-09，禁止用固定平移补偿。

转换审计记录接口、方向、批次、输入/输出坐标系、转换时间和数量。原始高德字段/坐标是否可保存，仍受下述授权边界约束。

## 推荐实施范围

第一阶段实现一个 `AmapPoiSource` 和独立验证任务。地理编码、路线服务、地图渲染继续按现有架构，不要求实现第二套完整 MapProvider。任务对同一社区、同一半径、同一采集窗口运行百度和高德，分别规范化后生成候选，不直接把结果取并集计入评分。

数据模型需保留来源内标识、来源坐标系、采集时间、查询策略版本、类别原值及来源失败/截断状态。来源未提供更新时间时记 `observed_at=null`；`retrieved_at` 仅是抓取时间，不代表 POI 在该日期已被来源核实更新。

匹配采用类别相容、名称/地址相似、统一坐标后距离的组合策略，输出 matched、baidu_only、amap_only、ambiguous、conflict。50 米/100 米等阈值只能作为待校准的项目参数；同名连锁分店、建筑物与内部商铺、医院与诊所等不能按距离直接合并。暂不赋予任一厂商全局优先级：冲突保留，人工复核。

第二阶段选 2–3 个社区、3–5 类设施，人工标注 50–100 对候选。分别报告自动合并精确率、漏合并/错误合并、未决率、单源召回差异、截断/失败比例和坐标偏差；评估准确率必须使用人工或官方独立证据，不把高德自动当真值。

第三阶段在许可、质量和预算允许后增加运行时双源开关。高德失败时报告来源不完整，不能把失败空列表解释为没有设施。是否融合 POI 计数、是否显示高德来源结果和是否落盘，根据授权和实测结果另行决定。
