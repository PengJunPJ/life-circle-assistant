# 2026 上海开源软件应用创新大赛：官方要求基线

> 核验日期：2026-10-09（Asia/Shanghai）  
> 适用项目：百度地图企业命题《基于地图开放能力的“15 分钟生活圈”智能体检与规划助手》  
> 用途：作为项目差距审计的外部要求基线；本文只记录可由第一方材料支持的事实，不把项目自述当作赛事规则。

## 结论摘要

1. 当前官方赛程为：报名及作品提交截止 **2026 年 10 月 16 日 24:00 前**，10 月 21 日公布入围名单，10 月 29 日线下总决赛。赛事总周期为 8 月 5 日至 10 月 29 日。[S1][S3]
2. 官网要求报名后按确认邮件指引提交作品；官网同域内容包明列的作品材料包括：**完整可运行代码的仓库链接、作品介绍文档（推荐 PDF）、作品演示视频链接**。材料须在 10 月 16 日 24:00 前发送至 `oscc@oschina.cn`。[S1][S7]
3. 百度地图命题另有三类专项交付物：开源源码与标准许可证；一键构建/部署及自动化测试脚本、示例数据、Docker 或环境配置；覆盖 API 策略、等时圈算法、POI 清洗、盲区识别和真实社区对比测试的技术文档与报告。[S2][S4]
4. 官方同时公布了两套评分：大赛通用评分为 **技术创新 30% / 场景落地 30% / 开源治理 20% / 长期发展 20%**；百度地图命题专项评分为 **功能正确性与覆盖率 40% / API 深度调用与工程优化 30% / 产品交互与用户体验 15% / 开源工程规范 15%**。[S5][S2]
5. 官方没有公开说明两套评分如何折算，也没有声明专项评分替代通用评分。因此严谨的准备方式是**两套同时满足**，不能自行选一套，也不能把权重相加成一张百分表。

## 4. 百度地图命题的硬性功能目标

官方命题记录和 PDF 要求参赛团队：[S2][S4]

- 基于百度地图开放能力开发 Web 或小程序；
- 至少覆盖地理编码/逆地理编码、POI 兴趣点检索、路径规划与距离计算；专项评分还明确要求坐标转换、POI 检索和路径规划能够稳定调用；
- 选择所在城市任意社区或街道作为样例，并允许输入中心点坐标；
- 基于**真实路网**自动计算 15 分钟步行等时圈；
- 统计圈内民生设施覆盖，输出可视化体检报告；
- 自动标注设施匮乏的灰色区域；专项评分将盲区具体化为“周边 1 公里内没有菜市场、药店或小学”的点位。

由此得到的严格判断：离线合成数据、直线距离或演示降级可以用于复现和兜底，但不能冒充“真实路网”的正式结论；扩展更多设施类别可以加分，但不能替代菜市场、药店、小学这三类明确评分对象。

## 5. 百度地图命题专项交付要求

### 5.1 开源应用源码

- 完整项目代码托管于 Git 平台，例如 Gitee 或 GitHub；
- 附带标准开源许可证，例如 Apache-2.0 或 MIT。[S2]

### 5.2 构建与自动化测试脚本

- 提供一键式编译或部署脚本；
- 配置示例数据；
- 使用 Docker 或环境配置文件，让评审方可以快速跑通演示。[S2]

### 5.3 技术设计文档与报告

- 地图 API 调用策略；
- 等时圈生成算法，以及如何基于路网计算可达范围；
- 多源 POI 数据清洗策略；
- 服务盲区识别算法；
- 针对特定社区的**真实对比测试报告**。[S2]

“真实对比测试报告”是命题明列交付项，不应降格为可选优化。报告至少需要让评审识别样例社区、测试日期、数据来源、对比方法、指标结果和限制，才能证明它确为可核验的真实对比，而非产品截图或同源自证。

## 6. 两套官方评分基线

### 6.1 大赛通用评分

| 维度 | 权重 | 官方关注点 |
| --- | ---: | --- |
| 技术创新 | 30% | 技术路线独创性；是否解决已有方案未解决的问题；相较同类是否有明确优势 |
| 场景落地 | 30% | 可部署、可运行、可测试；场景真实、方案适配；验证数据来自真实或仿真环境 |
| 开源治理 | 20% | 协议与依赖合规；贡献机制和文档规范清晰；新项目看规划、老项目看运营 |
| 长期发展 | 20% | 持续维护能力、长期规划、治理结构与社区或组织支撑 |

来源：官方评分 API。[S5]

### 6.2 百度地图命题专项评分

| 维度 | 权重 | 具体评分点 |
| --- | ---: | --- |
| 功能正确性与覆盖率 | 40% | 稳定调用坐标转换、POI 检索、路径规划；准确渲染真实路网等时圈热力图；准确识别 1 公里内无菜市场、药店或小学的服务盲区 |
| API 深度调用与工程优化 | 30% | 批量距离矩阵或并发策略降低耗时；处理 POI 缺失、API 异常和 QPS 限流；通过空间插值或扇形采样合理推导近似连通区域 |
| 产品交互与用户体验 | 15% | 热力图、柱状图、雷达图等直观展示；地图交互流畅；界面美观；用户可自定义中心点；操作逻辑清晰 |
| 开源工程规范 | 15% | 结构、模块和命名规范；README 详尽，含 API Key 脱敏、环境变量和部署说明；配置 GitHub Actions 或 Gitee Go 等自动构建及代码格式检查 |

来源：官方百度地图命题 PDF 第 1–2 页。[S2]

### 6.3 评分关系的严谨处理

官网通用评分与企业命题 PDF 专项评分同时存在，但公开材料没有说明两者的折算公式、评审阶段或优先级。因此：

- 不应声称专项 40/30/15/15 已覆盖大赛通用 30/30/20/20；
- 不应把两套权重直接相加或平均；
- 项目审计应分别建立两张证据矩阵；
- 尤其不能漏掉通用评分中的贡献机制、治理规划、持续维护和社区支撑，这些在专项功能表中没有充分展开。
