# 专家 1（地理位置开发主任）报告：AI 优先的地理计算与“15 分钟生活圈”方案

核验日期：2026-10-13（Asia/Shanghai）  
报告对象：百度地图企业命题《基于地图开放能力的“15 分钟生活圈”智能体检与规划助手》  
本报告只写地理、地图 API、空间计算和空间智能建议；语言模型不能替代路线服务、坐标转换、空间计算或规划审批。

## 1. 结论先行

建议采用“**确定性地理内核 + AI 主动测量与解释层**”的方案：

1. **地图 API/路网是事实来源**。模型可以决定测什么、解释为什么、提出候选点，但不能自行生成路线距离、设施存在性或等时圈几何。
2. **把两个问题分开呈现**：
   - “1 公里内是否有设施”是设施稀缺指标，使用网格中心到设施的直线距离（或明确选择的空间距离），不等于步行可达。
   - “15 分钟能否步行到达”是路网可达指标，使用提供方步行时间，受道路连接和入口影响。
   现有 `lacks_nearby_facility` 字段已经保存第一项证据；增量应是独立图层、计数和结论，而不是无条件推翻现有四态分类。
3. **正式等时圈优先评估百度 Isochrone API**（`foot_fastest`/`foot_shortest`），并保留当前径向采样作为跨权限兜底与算法创新旁路。当前仓库没有证据表明该接口已经接入、已获账号权限或已计费验证，不能在报告中把它写成现有能力。
4. 如果继续自行采样，AI 的价值应放在“**主动选择下一批最有信息量的路线样本**”：道路屏障附近、时间阈值附近、相邻方向预测分歧大的点优先调用 API；模型只在已有观测之间给出带置信区间的估计，接近 15 分钟阈值时必须转回 API 或标记未知。
5. 规划建议采用“候选点生成 -> 少量路网精算 -> 原报告不可变的情景复算”。模型不能直接宣布“建在哪里”，只能排序有证据的候选点并显示改善量、成本假设和不确定性。

这条路线同时服务专项评分的四个边界：功能正确性与覆盖率 40%、API 深度调用与工程优化 30%、产品交互与用户体验 15%、开源工程规范 15%。这四项权重来自赛题 PDF，不能用模型演示替代前三项的真实 API 证据。

## 3. 地理内核：两个指标、三个坐标和四个证据层

### 3.1 设施稀缺与步行可达必须独立

对每个网格单元 `g`、设施类别 `c`，建议保存以下原子事实：

```text
nearby_count(g,c) = count(facility in c where straight_distance(g.center, facility) <= 1000m)
reachable_time(g,c) = min(successful walking route(g.access_point, facility.access_point))
```

推荐展示矩阵：

| 1 公里内设施 | 15 分钟步行 | 解释层 |
|---|---|---|
| 有 | 是 | 正常覆盖，但仍可提示设施集中度/入口质量 |
| 有 | 否 | 路网绕行或屏障导致的可达性问题（现有 `sparse`） |
| 无 | 是 | **设施稀缺但可达**，满足赛题“周边 1 公里内无设施”的独立指标；不应伪称路网盲区 |
| 无 | 否 | **重点服务盲区**，同时满足稀缺和超时 |
| 证据不完整 | 任意 | `unknown`，不以零设施或无限分钟替代 |

现有分类器已经在 `service_areas.py` 保存 `lacks_nearby_facility`，并把“无近邻但仍可达”归入 `sparse`。建议增加：

- `scarcity_status`：`present`、`scarce`、`unknown`；
- `walk_access_status`：`within_threshold`、`over_threshold`、`unknown`；
- 独立的 `scarcity_layer` 和 `critical_access_layer`；
- 报告分别统计“稀缺网格数”“超时网格数”“双条件重点盲区数”，不把三者相加为居民数。

这样既保留当前实现的四态兼容性，又完整响应赛题 1 公里盲区评分点。

### 3.2 设施点、楼宇和可服务入口不是同一坐标

每个设施建议使用三种坐标：

1. `geometry_point`：POI 原始位置，用于地图显示和空间近邻。
2. `access_point`：`navi_location`、子 POI 入口或人工校验入口，用于路线终点。
3. `service_area_point`：如果设施为大型面状 POI，表示真正向居民提供服务的门/服务台，可有多个入口。

路线证据应保存 `origin_access_source`、`destination_access_source`、`uid`、入口选择规则和时间戳。若没有入口字段，退回 POI 点并把 `entrance_assumed=true` 写入质量事件。无法确认小区门禁、学校非公众入口、医院夜间入口、市场营业时间时，结论必须标记为“地图路网可达，不代表开放/无障碍可服务”。

百度路线的 `road_prefer=3` 是“无逆行且无阶梯”的算路方案；这不能扩展解释为完整无障碍路线，也不能替代轮椅、婴儿车和现场门禁核验。

### 3.3 坐标合同

建议内部 API 继续统一 BD-09，但在数据结构中显式写：

```json
{
  "coordinate_system": "BD-09",
  "coordinate_order": "lng,lat",
  "geometry_source": "baidu_place",
  "access_point_source": "baidu_navi_location|manual|assumed"
}
```

GeoJSON 标准 RFC 7946 要求坐标使用 WGS 84、经度在前纬度在后；因此对外导出的 GeoJSON 必须转换为 WGS84，或明确这是内部 BD-09 交换格式并阻止外部 GIS 误读。来源：[RFC 7946 第 4 节](https://www.rfc-editor.org/rfc/rfc7946#section-4)，事实状态：已查证。

## 4. 等时圈：确定性基准与 AI 主动采样

### 4.1 优先路径：原生等时圈 API

若账号允许，调用 `foot_fastest` 生成主等时圈，并将 API 返回的几何、请求参数、响应摘要、坐标转换和时间戳原样留证。随后用少量独立点做路线矩阵交叉检查：边界内点应大部分不超过阈值，边界外点应大部分超过阈值。原生等时圈的具体孔洞、断片、时间边界和计费行为仍需真实账号验证；未验证前不要承诺“精确到每一栋楼”。

### 4.2 兜底路径：障碍感知主动采样

当前扇形采样可以保留，但应从“固定 16/24 方向 + 单调二分”升级为“**分层采样 + 主动学习 + 证据边界**”：

1. 初始层：中心、16 个方向的 3 个半径（例如 400/800/1,250 米），优先使用步行矩阵；批量请求严格按 50 路线分块。
2. 特征层：局部方向、直线距离、已有路线时间、路线/直线比、失败标志、POI/道路密度、河流/铁路/高速等屏障代理特征、是否跨大型封闭 AOI、相邻方向时间梯度。
3. 模型层：预测每个候选点的 `t_walk` 和 `P(t_walk <= 900s)`，输出预测区间而非单点；可以用梯度提升/高斯过程等轻量模型，模型只消费 API 观测和经现场核验的数据。
4. 主动选择：优先调用以下点：
   - 预测时间接近 900 秒的点；
   - 相邻方向预测分歧大或置信区间宽的点；
   - 直线距离相近但路线/直线比异常大的点；
   - 路线失败、跨河/铁路/围墙等候选障碍两侧的点；
   - 网格分类会因该点改变（稀缺/可达与重点盲区边界）的点。
5. 停止层：只有当边界相邻单元的区间都不跨越 900 秒且空间间隔达到验收阈值，才停止；否则继续调用 API。接近阈值的点一律不由模型单独裁决。
6. 成面层：使用观测点和预测概率构建带置信度的栅格/三角网，再通过路网边界点和障碍约束成面；不得简单连接相隔很远的扇形端点。报告同时返回 `observed_boundary`、`estimated_boundary`、`uncertain_band`。

当前二分的具体限制：代码假定同一射线时间随半径单调增加，固定 1,250 米可能截断 20 分钟范围；围墙、河道和多入口会造成不单调、孔洞或断片。AI 只能减少 API 次数，不能证明这些假设成立。

### 4.3 误差边界与人工核验

对每个网格/边界点应报告：观测 API 时间、模型预测时间区间、距阈值的安全裕度、样本来源和最后核验时间。可使用 split conformal prediction 形成分布无关的有限样本预测区间，但其覆盖保证依赖校准样本与未来样本可交换等条件；城市施工、天气和地图版本变化会破坏条件，不能写成绝对误差保证。参考：[Angelopoulos & Bates, *A Gentle Introduction to Conformal Prediction*](https://arxiv.org/abs/2107.07511)（方法背景已查证）。

推荐三档：

- `high`：API 直接观测，路线成功，入口已确认；
- `medium`：API 观测+模型插值，区间不跨阈值但现场入口未核实；
- `low/unknown`：API 失败、模型区间跨 900 秒、设施检索截断或只有单一假设入口。

## 5. POI 多源清洗与可服务性

### 5.1 百度主源清洗

保留 `uid`、原名、类别原值、标准类别、geometry、`navi_location`、地址、子 POI、来源、检索页码、采集时间和状态。规范化可以做 NFKC、空白/标点处理、类别映射和同机构去重；不能仅凭相似名称合并连锁分店、不同校区或医院科室。当前 [facility_normalization.py](../../backend/app/analysis/facility_normalization.py#L120) 的 80 米同机构规则应输出合并理由、置信度和原始记录数，这一点已经具备。

应新增或明确以下状态：`discovered`、`entrance_known`、`open_status_known`、`public_service_assumed`、`stale_or_unknown`。设施“被检索到”不等于“真实存在、营业、对公众开放且能满足目标服务”。

### 5.2 第二来源只做观察，不直接并集计数

高德等第二来源可用于交叉观察，但授权和存储范围必须先确认；现有研究已指出高德协议对缓存、数据库、算法训练和传播有额外限制（见 [amap-multisource-feasibility-2026.md](./amap-multisource-feasibility-2026.md)）。在授权未明确前：

- 不把百度/高德并集直接当作设施总数；
- 不把两源一致率称为地面准确率；
- 只保存按许可允许的脱敏匹配结果；
- 用人工实地记录、官方名录或现场照片作为独立验证。

建议人工标注 50–100 对实体，覆盖同品牌门店、学校校区、医院科室、迁址/关闭设施和大型 POI 入口，报告错误合并率、漏合并率、未决率、类别错配和坐标偏差。

## 6. API 成本、QPS 与数据新鲜度

### 6.1 路线预算

每次任务应先估算路线对：

```text
route_pairs = 设施中心路线 + 等时圈主动样本 + 网格×候选设施 + 规划候选点复算
http_requests = ceil(route_pairs / 50)（仅矩阵部分，实际还包括失败重试和单条路线）
```

服务端共享令牌桶、并发信号量和单任务预算；重试次数不应在客户端、步行包装器、业务层无限叠加。每个 HTTP 请求记录：API、请求批次大小、路线对数、重试次数、缓存命中、限流/超时、业务状态码和最终证据状态。缓存键须含提供方、方向性起终点、出行方式、入口来源和规则版本，不能把反向路线或不同提供方结果混用。

### 6.2 POI 完整性

地点检索必须翻页到预设上限并记录 `total`、`page_num`、`page_size`、`radius_limit` 和截断状态；对网格边缘做补充检索，但不能通过无限切片规避提供方上限。没有翻页证据的类别只能说“当前检索窗口发现”，不能说“社区无设施”。

### 6.3 新鲜度与实时性

路线耗时是提供方在请求时的计算结果；它不自动等于现场实测，也不自动披露红绿灯等待、施工围挡、门禁和无障碍。报告应使用“地图服务在 `retrieved_at` 的步行估计”措辞，并把实地时间、开放时段和入口核验作为独立证据。

## 7. AI 交互入口的地理安全边界

建议把大模型置于工具编排层，工具白名单至少包括：

1. `resolve_location`：地址/地图点候选，返回坐标、坐标系和候选理由；模型不得自己写经纬度。
2. `search_facilities`：类别、半径、分页和来源状态；返回检索窗口而非“全量”承诺。
3. `measure_routes`：批量起终点、UID/入口来源、时间和失败原因。
4. `get_isochrone`：原生等时圈或主动采样任务，返回几何与质量字段。
5. `inspect_cell`：独立稀缺、步行可达、候选路线和证据状态。
6. `simulate_facility`：只接受报告已有类别/候选点或经用户确认的地图点，生成不可变情景报告。

模型输出必须带 `evidence_refs`，数值由工具结果直接渲染；缺少证据时使用“无法判定/需要补测”而不是补全。用户说“河边那片”“学校旁边”时先返回可编辑候选，不得将视口中心默认为分析中心。规划建议必须说明：候选点、影响网格、预计变化、路线重算次数、数据来源和未知项。

这种交互能显著降低地图操作门槛，但不会降低地理事实门槛。模型可解释路线绕行原因、比较“新增药店”和“改善入口”的方案、生成面向居民或规划师的两种报告，却不应制造 POI、篡改阈值或把估算写成真实 API。

## 8. 规划优化与复算

候选点生成可采用网格中心/盲区簇 medoid、道路可达候选点、用户指定点和可用地约束的交集。对每个候选点：

1. 先用直线距离和现有路网缓存做粗筛；
2. 只对 Pareto 前沿候选调用百度步行矩阵（路线对严格按 50 分块）；
3. 重算受影响设施类别的网格、稀缺状态、15 分钟状态和评分；
4. 报告 `before/after/delta`、改善网格、覆盖面积估计、API 样本和未覆盖因素。

优化目标应是多目标而非只追求一个总分，例如：

```text
min 重点盲区数、超阈值网格面积、最坏 P95 步行时间、API/建设成本
subject to 入口可用、用地/容量/类别约束和数据置信度下限
```

人口、服务容量、学区招生、医疗资质、营业时间和用地可行性目前不在地图 POI 路线 API 中；在这些数据未接入前，模型只能说“地图可达性改善候选”，不能说“规划一定有效”。

## 9. 现场核验与验收指标

建议选择一个黄埔区社区做盲测，采集不少于 30 个起终点对，覆盖桥梁/河道、封闭小区、学校/医院入口、道路交叉口和不同设施类别；分时段记录 GPS 轨迹、实际出发/到达时间、入口照片和开放状态。将数据按 API 请求时间冻结，避免把后续地图更新混入验证集。

最少验收指标：

| 指标 | 建议门槛/披露 |
|---|---|
| 三类核心设施 1 公里稀缺识别 | 逐网格给出计数、检索完整性和人工抽查，不用单一准确率掩盖截断 |
| 15 分钟二分类 | 报告准确率、召回率、阈值附近混淆矩阵；把未知和模型估算单独列出 |
| 步行时间误差 | MAE、P90 绝对误差、路线失败率，按入口/屏障分层 |
| 边界几何 | API/人工检查点到估计边界距离、孔洞/断片误报；披露 1,250 米上限截断 |
| API 工程 | 路线对数、HTTP 请求数、缓存命中、限流、重试、P95 耗时和成本 |
| POI 清洗 | 错误合并率、漏合并率、类别误判率、入口可用率、状态未知率 |
| AI 可靠性 | 工具调用成功率、无证据数字比例、人工改写比例、模型 abstain 比例 |

## 10. 分阶段落地优先级（按专项评分映射）

### P0：正确性（40%）

- 三类核心设施独立输出 1 公里稀缺图层和“双条件重点盲区”。
- 所有真实模式结果显示来源、检索时间、路线对失败和入口假设。
- 将矩阵步行默认分块改为公开契约 50；零值/无解和失败状态分离。
- 完成一个社区的现场配对核验和真实对比报告。

### P1：API 深度与优化（30%）

- 申请并验证 Isochrone API；与主动采样等时圈做旁路对比。
- 引入 50 对路线预算、统一令牌桶、缓存和逐 HTTP 可观测性。
- 用 AI 选取阈值附近/障碍两侧样本，减少无信息 API 调用；任何低置信度区域自动补测。
- POI 翻页、入口/UID、边缘网格补检和多源人工标注。

### P2：交互体验（15%）

- 以自然语言开始，展示候选位置/类别/时间参数预览，用户确认后才启动分析。
- 对“为什么是盲区”“新增设施效果如何”“哪个入口影响最大”提供工具证据链和地图高亮。
- 同一份报告支持居民易读解释和规划师技术证据视图。

### P3：开源工程（15%）

- 文档固定坐标系、API Key 脱敏、真实/快照/模拟/估算边界和复现实验命令。
- 提供合成 fixture、现场数据脱敏规则和 CI 检查；不把受限来源原始 POI 响应直接提交仓库。
- 记录模型版本、提示模板、工具 schema、规则版本和数据质量事件，确保结果可复算。

## 11. 专家 1 的最终决策建议

最优地理路线不是让大模型“计算等时圈”，而是让模型成为**地理测量调度员、证据解释器和方案比较器**：确定性 API 产生事实，空间算法维护拓扑和阈值，AI 将有限的路线预算花在最有信息量的位置，并在证据不足时主动承认未知。第一版优先修正 50 路线契约、POI 翻页/入口、1 公里独立指标和 GeoJSON 坐标披露；第二版再把原生 `foot_fastest` 等时圈与主动学习边界并列验证。这样能最大化 AI 融入，同时不牺牲赛题 40% 功能正确性这一硬约束。
