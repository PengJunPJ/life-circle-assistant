# 多方案比较

## 使用

完成体检后，在右侧“可解释 AI 规划助手”选择比较目标，然后点“比较方案”，或直接提问，例如“比较减少菜市场盲区的可行方案”。方案位置来自当前报告的规划候选点；地图选点可作为不同类别方案的共同假设位置。启用模型时，由支持原生 `tools` / `tool_calls` 的模型按问题选择二至三个方案。未启用模型时，规则流程从报告候选点中组织方案。计算结果返回后，逐项点击“在地图查看”，不会再次计算。

目标有三种：减少重点盲区（重点盲区网格数下降）、扩大分类覆盖（该类别正常与稀疏网格面积之和增加）、提高综合指数。可比较性不满足时会说明排除理由，而不是补造缺失结果。

## 算法和边界

每个方案分别把一个假设设施加入报告快照并调用既有 `ReportSimulationService`，所有方案都从同一份不可变原报告开始，不会把前一个方案叠加到后一个方案。服务端计算增量、检查数据完整性并排名；模型不得生成坐标、增量、成本或排名。仅完整且空间范围可比的计算参加排名。路线失败、未知网格、无网格类别或不完整评分不会排名。并列保留；只有至少两个可比较方案且目标确有正改善时才给出优先方案。

覆盖面积使用现有服务网格 `normal` 与 `sparse` 的面积，不等同于人口覆盖、住户覆盖或严格等时圈面积。重点盲区数基于现有网格分类。综合指数目标仅支持原报告类别评分完整的报告，避免类别权重重新归一化改变比较基线。排名是目标单项的技术比较，不是成本效益或规划可行性结论。

本功能不计算建设成本、用地权属/许可、设施容量、人口受益、组合选址或多设施协同，也不替代实地步行核验。候选点不是建设承诺。地图、报告快照、缓存或离线合成数据的来源质量按原报告提示展示。每轮最多执行一次单设施模拟或一批二至三个方案比较，工具总调用上限六次，端到端预算九十秒。批次按顺序计算；超时会保留已完成方案，并将未完成项标记出来，不对未完成项排名。

方案比较随规划助手轮次写入已有 AI 解读存储与报告导出；后续追问沿用服务端保存的工具上下文。详情见 [工具规划助手说明](工具规划助手.md)。
