# V2.0.0 发布说明

## 发布结论

`2.0.0` 已完成赛事交付范围内的功能实现、自动化验证和 Docker 演示闭环，可作为“可信、可解释的生活圈分析”功能型 Beta 发布。

本版本强调结果可追溯、限制可见和离线可复现。它不是生产级规划决策系统，真实结论仍需多社区、全网格和跨数据源验证。

## 发布范围

- 分析中心：地址候选、地图选点和坐标输入保持一致。
- 空间分析：按菜市场、药店、小学和医疗服务分别计算步行覆盖和风险网格。
- 可信说明：报告披露真实 API、缓存、本地快照、降级估算和部分失败。
- 规划辅助：生成有依据的建议，并模拟新增设施后的评分和盲区变化。
- 报告管理：持久化历史报告，支持重新运行、比较和多格式导出。
- 交付能力：提供 Docker Compose、统一质量检查和无凭证离线演示。

## 数据可信度边界

- 离线模式只用于稳定演示和自动化测试，界面与报告必须保留“非实时数据”提示。
- 固定中心点的真实核查中，旧快照标出的 7 个重点盲区只有 3 个获得同等级实时证据支持。
- 当前核查没有覆盖全部类别网格，因此不能计算完整准确率、召回率或混淆矩阵。
- 正式规划使用前，应补充多个真实社区、独立数据源和现场道路条件核查。

## 回滚与兼容性

- 公开分析接口继续保留 `POST /api/analyze`、`GET /api/analyze/{task_id}` 和 `GET /api/report/{task_id}`。
- V2 报告新增字段，不移除 V1 的核心字段；报告契约版本为 `2.0`。
- 应用发布版本为 `2.0.0`，与报告契约版本分别管理。
- Docker 健康检查热修复只改变 Web 容器探针地址，可独立回滚，不改变业务行为。

## 发布后优先事项

1. 在 Gitee 提交和 Pull Request 上启用可执行的质量门禁。
2. 建立 3～5 个真实社区基准数据集并完成全网格复核。
3. 统一设施语义和同址机构归并规则。
4. 将报告内部的动态字典逐步收敛为强类型模型。
5. 补充生产部署、监控、备份和密钥管理方案。

Gitee 门禁的官方能力、实施顺序和待实跑风险见 [Gitee Go 质量门禁落地调研](../research/gitee-go-quality-gate.md)。当前仓库尚未开通 Gitee Go，因此不能把已有 GitHub Actions 配置描述为 Gitee 上已生效的强制门禁。
