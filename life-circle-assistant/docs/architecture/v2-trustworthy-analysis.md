# V2 可信分析技术说明

## 数据来源与调用策略

`SnapshotMapProvider` 用于无凭证的可复现演示，`BaiduMapProvider` 用于实时地图服务。真实模式先按类别逐关键词检索 POI，再按 `uid`、规范化名称和六位坐标去重。直线距离仅用于候选预筛，最终覆盖和网格分类使用步行路线。

步行请求通过统一服务层处理缓存、超时、有限重试、并发和 QPS；成功结果记录提供方、起终点、计算方式和有效期。无法获取路线时保留失败原因，必要时只生成部分报告，不伪造实时结果。

## 等时圈与服务盲区

等时圈按 16/24 个方向采样，分析模式增加边界二分细化。采样失败会出现在 `data_quality.events`，不足时使用明确标记的降级边界。统一 4×4 BD-09 网格逐类计算：最近同类设施超过阈值且 1 公里内没有同类设施为重点盲区；只满足一项为设施稀疏区；两项均不满足为正常覆盖区。每个网格记录最近设施、步行时间、距离、数据来源、计算方法和置信度。

## 评分、规划与模拟

类别评分由设施数量、最近步行时间和四象限空间分布组成。检索失败或步行结果不完整的类别不计入综合分；确认零设施的类别得到 0 分，避免“没有数据”与“真实缺失”混淆。规划建议引用具体盲区网格并给出候选点和预计改善范围。模拟只复制来源设施并加入假设设施，重新计算受影响类别，来源报告保持不可变。

## 持久化、降级与质量披露

SQLite 保存任务、请求参数、报告和步行缓存。服务重启会将遗留运行中任务标记为中断。报告的 `calculation_mode`、`execution` 和 `data_quality` 必须同时展示提供方模式、缓存命中、降级估算、失败类别和限流/超时事件。合成离线种子带有 `is_synthetic` 标记，不能解读为最新真实 POI。

## 复现入口

无凭证运行 `BAIDU_MAP_MODE=mock make quality` 可完成后端测试、前端检查、生产构建以及容器构建和冒烟验证（需要本机 Docker daemon）；若仅需离线验证代码与 Compose 文件，可分别运行 `make backend-check`、`make frontend-check` 和 `docker compose config --quiet`。有凭证时将模式切换为 `real`，先小范围人工核查再运行性能基线。固定社区的人工核查、差异分类和限制见 [`v2-real-community-comparison.md`](../validation/v2-real-community-comparison.md)。
