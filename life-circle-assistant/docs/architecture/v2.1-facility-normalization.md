# V2.1 设施语义归一化

## 目标

多关键词检索可以提高设施召回，但同一医疗机构可能同时以医院主体、发热门诊、急诊科和预防接种门诊出现。如果直接把每条 POI 作为独立设施，数量评分、空间分布和最近设施候选都会被虚增。

## 模块 seam

`normalize_facilities(facilities)` 是唯一对外 interface。地图提供方返回原始设施后，分析编排先经过该模块，再进入步行计算、服务区域、评分、建议和导出。

```text
地图提供方原始设施
  └── normalize_facilities
        ├── 名称标准化
        ├── 语义子类判定
        ├── 机构主体提取
        ├── 同址同机构合并
        └── 别名与规则摘要
              └── 步行 / 服务区域 / 评分 / 报告
```

该模块是纯计算模块，不访问网络或数据库。规则修正只发生在一处，且可通过同一 interface 直接验证。

## 合并规则

1. 同设施类别且提供方标识一致的记录合并。
2. 名称去除全半角、空白和标点后一致，且坐标在 80 米内的记录合并。
3. 医疗设施去除“发热门诊”“急诊科”“预防接种门诊”等下属名称后，机构主体一致且坐标在 80 米内的记录合并。
4. 区县前缀不同但主体名称互为包含、长度足够且同址的医疗记录可合并，置为中等置信度。

仅坐标相近不构成合并依据。药店门店名、学校校区名和市场名不会因为同址而被删除。

## 报告契约

每个设施新增：

- `canonical_name`：机构规范名称。
- `semantic_type` / `semantic_type_label`：规则推断的语义子类。
- `normalization`：规则版本、合并方法、置信度、别名、原始标识和原始记录数。

顶层 `facility_normalization` 记录输入、输出、合并数量与分类别语义统计。这些都是 V2 契约的增量字段，不移除现有字段。
