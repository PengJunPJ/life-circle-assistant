# AI 融合实施与验证说明

日期：2026-10-13。依据：[综合方案与专家评审](../../../docs/AI大模型融合方案与专家评审.md)。本轮交付是可运行的增量实现；真实外部服务效果与远期路线图分别记录。

## 使用路径

按项目 README 启动，保持 `BAIDU_MAP_MODE=mock`、`LLM_ENABLED=false` 即可离线体验。首屏“对话工作台”与地图、参数表单、报告和图层共享状态；规则模式会明确标识，配置模型后仍执行相同的工具与事实校验。

1. 输入“体检沙涌长盛花园，步行15分钟，关注买菜和买药”。检查解析参数，通过位置候选或地图选点确认中心。未知地点不会自动替换为默认位置；离线模式只支持内置样例。
2. 输入“开始体检”，核对执行提示后点击“确认执行”。任务进度显示在工作台，可取消；失败或取消后可以“重新体检”。重试根据保存参数创建新任务，保留来源记录，不是断点续算。
3. 报告完成后输入“只看菜市场”“最近的历史报告”，或点击网格后输入“解释这个区域”。图层、网格和报告与现有界面联动。
4. 输入“语义审核设施”，确认后查看分类与实体关系建议；输入“主动采样实验”查看离线采样对照。样本不足会显示原因。
5. 输入“覆盖优化，最多三家菜市场”，核对候选范围和数量上限后确认；输入“导出 PDF”并确认可导出当前报告。

会话及参数保存在 SQLite，浏览器保存工作区标识，刷新后恢复。新的消息或参数修改使旧确认失效。多页面修订冲突会读取最新状态；旧请求重放只恢复历史，不再执行过期界面动作或导出。开始分析后当前界面暂时禁用新对话输入，保留进度与取消入口。

## 已实现能力与计算边界

| 能力 | 实现与正确性约束 |
|---|---|
| 事实回答 | 模型仅提交 `{report_id,type,id,slot}`。服务器校验报告、对象、槽位，填入数值与事实文本；跨报告、未知槽位、夹带自由文本或数值的模型输出降级。普通解读与规划问答使用同一门禁。 |
| 持久对话 | SQLite 事务预留消息；相同请求标识和内容返回缓存结果，不重复执行；异内容同标识、执行中请求和修订冲突返回 409。启动时把中断轮次标为失败，不自动重放收费操作。 |
| 地图契约 | 百度矩阵分块每批最多 50 路线对；非同点零值保持未知；设施分页披露完整性及截断；归一化聚合来源、UID 和导航入口证据。内部仍为 BD-09。 |
| 缺口分析 | 1 公里直线稀缺与步行阈值分别统计。已确认步行超时网格按类别、四邻接分组，保留原网格多边形与孤立缺口，未知不参与；几何邻接不代表道路连通。 |
| 语义审核 | 规则与可注入嵌入接口召回候选，大模型可提出有原字段依据的分类/实体关系建议；类别相同不等于同一门店。建议不自动改设施主数据、坐标、正式类别或评分。自报置信度不作为校准概率。 |
| 主动采样实验 | 小样本高斯过程选择补测点，与同训练样本的反距离加权对照。报告接口只复用有来源的既有路线，去重并按 500 米空间块留出；预测标为实验，不进入正式可达性、盲区或评分。 |
| 有限候选优化 | 使用报告候选、已确认重点盲区网格及新的步行路线，最大化不同网格中心覆盖；支持数量和完整成本数据下的预算硬约束。十万组合内精确枚举，否则确定性贪心；未知路线是覆盖下界。 |

原报告保持不可变。覆盖优化的 `OPTIMAL` 只表示输入候选及已确认覆盖集合中的最优；`FEASIBLE` 表示贪心可行解。结果不是连续面积、受益人口、建设许可或组合评分改善，不累加单点模拟分数。

对话覆盖优化支持 1–8 个数量上限，默认 2 个，按候选标识排序最多纳入 16 个候选并披露截断。预算、成本、用地、容量等自然语言限制缺少结构化证据时会拒绝该操作，避免静默忽略；最低数量、按类别分别限量和多个数量约束也会明确拒绝。需要成本约束时使用下面的结构化接口。

## 新增接口

接口均为同源 `/api`；用 `GET /api/reports/history` 获取已有报告标识，报告候选标识来自报告 `recommendations[].candidate_locations[].id`。不接受客户端提供训练路线标签或伪造候选坐标。

| 请求 | 输入与行为 |
|---|---|
| `POST /api/workspaces` | `{"state": {...}}`，创建工作区；未指定状态时使用服务端默认值。 |
| `GET /api/workspaces/{id}` | 返回状态及 `revision`。 |
| `POST /api/workspaces/{id}/state` | `{"expected_revision": 0, "state": {...}}`，更新共享状态；绑定报告/任务必须匹配位置、分钟、模式及类别。 |
| `GET /api/workspaces/{id}/messages` | 最近 100 个已结束轮次，按时间顺序返回。 |
| `POST /api/workspaces/{id}/messages` | `{"request_id":"ask-1","expected_revision":0,"message":"只看菜市场"}`；确认另发新的请求标识及 `confirm_token`，使用最新修订号。 |
| `POST /api/analyze/{task_id}/cancel` | 取消排队或运行任务，终态取消保持原终态；已取消任务不能发布报告。 |
| `POST /api/analyze/{task_id}/retry` | 失败/取消任务按保存参数创建新任务；针对同一来源任务重复重试幂等。 |
| `POST /api/reports/{id}/ai/semantic-review` | `{"use_model":false}`；设为 `true` 且已配置模型时最多一次模型 HTTP 尝试，返回审核建议。 |
| `POST /api/reports/{id}/experiments/sampling` | `{"route_pair_budget":20}`，范围 2–200；预算是离线样本使用上限，不产生外部路线请求。 |
| `POST /api/reports/{id}/planning/coverage` | `{"candidate_ids":["候选标识"],"max_facilities":1,"method":"auto"}`；可增加 `budget` 与每个候选的 `costs`，最多 32 个候选，成本单位由调用方统一。 |

结构化覆盖优化启用预算时必须提供所有候选的非负有限成本，数量/成本/候选与求解规模验证在地图调用之前完成。样本来源不足会返回明确的实验状态，不补造预测标签。旧报告若缺少缓存基础来源，不作为可靠训练证据。

## 执行预算

当前预算约束路线对及模型请求次数，不是人民币费用报价：

- 持久对话每轮最多 7 次模型尝试、256 个逻辑路线对；语义审核执行阶段收紧为最多 1 次。对话轮次最长 100 秒，既有规划工具预算仍适用。
- 后台分析任务单独使用 5,000 路线对上限；确认卡片显示该分析预算，而创建任务本身不会在消息轮次里执行这些路线。
- 结构化覆盖优化最多 512 路线对、90 秒；语义审核接口最长 60 秒。
- 原生模型适配器按真实 HTTP 尝试计数，包括重试，预算耗尽后不再发送。未提供预算钩子的注入适配器保守按适配器调用计数，响应披露计数单位。
- 百度真实步行 HTTP 重试及批量回退扣减实际路线对账本；缓存命中不产生外部请求。响应同时提供逻辑请求数与实际 HTTP 路线对数。

上述共享总预算覆盖新增持久对话与扩展入口；既有独立解读/规划 API 仍沿用原入口的限制。地点查询、设施检索不是步行路线对，不计入这一账本，仍受原有地图节流及超时配置控制。

## 验证记录

本轮使用离线快照、确定性提供方、HTTP Mock 和浏览器 API 拦截数据，未请求收费地图/模型服务，也未提交或推送 Git。

后端：最终全量 `pytest -q` 为 366 个测试通过，耗时 205.92 秒；`ruff check .` 与 `ruff format --check .` 通过（95 个 Python 文件）。只有 Starlette 使用 AnyIO 弃用别名的既有警告，没有测试失败。

前端：31 个测试文件、136 个测试通过；TypeScript、ESLint 与生产构建通过。桌面 1440×900、平板 1024×768、手机 390×844 浏览器检查无页面异常、横向溢出或对话与地图控件重叠。浏览器检查使用固定拦截数据，不能代替真实端到端现场验证。

容器：`./scripts/container-smoke.sh` 通过构建、健康检查、Nginx 同源 API 转发和离线报告 PDF 冒烟。测试临时容器、网络及卷已清理。构建存在既有图表分块约 537 KB 提示；不影响本轮构建通过。

## 尚未验证与后续边界

- 未验证真实模型或嵌入模型的现场准确率；嵌入仅有注入接口，未自动下载权重或部署推理服务。
- 采样实验是单空间块、中心到已有设施的探索对照，使用报告中舍入到 0.1 分钟的提供方时间标签；不证明等时圈边界更准，也不证明节省 API。存在冲突的同坐标标签排除并披露。
- 原径向等时圈仍有单调假设、孔洞表达及约 1,250 米搜索边界等既有局限；本轮没有接入百度原生等时圈、步行路网 GNN、强化学习或居民图片反馈。
- 未引入经核验的人口、设施容量、地块和土地许可数据；成本接口输入也不代表系统掌握真实造价。
- 服务重启后中断任务需要显式重试；本轮没有跨进程断点续跑。BD-09 内部契约及原评分 ADR 保持原口径。

模块设计沿用 `codebase-design` 的计算/证据接口边界，把交互动作与地理计算分开；首屏设计按 `frontend-design-direction` 接入原地图布局和共享状态。新增对话承担真实操作与证据查询，而不是另建一套孤立聊天状态。
