# 应用技术说明

本页承接原应用 README 中的功能、接口与验证细节。项目介绍、安装部署、环境变量、贡献和许可统一见 [根 README](../../README.md)。

以下命令均从包含 `docker-compose.yml` 的应用目录 `life-circle-assistant/` 执行；先按根 README 安装所需依赖。

## 快照维护与历史缓存

离线快照标记为合成样例，不代表当前真实设施。需要更新快照时，在已安装后端依赖且不输出凭证的本地环境、从应用目录执行；抓取失败不会覆盖旧文件：

```bash
BAIDU_MAP_MODE=real PYTHONPATH=backend backend/.venv/bin/python backend/scripts/cache_baidu_snapshot.py
```

镜像随附 `backend/data/walking_cache_seed.json`（2026-09-28 历史真实测算快照），缓存为空时导入并按启动时刻重盖 TTL；命中情况通过报告指标与 `walking_cache_used` 质量事件披露。历史样例的耗时见 [性能基线](performance/v2-baseline.md)，不作为任意社区的性能承诺。需要验证现场冷缓存分析时，关闭导入并使用新的独立数据存储，不能把历史缓存命中当作现场新测量。

## 功能与接口说明

### 自然语言发起体检与大模型解读

首屏的“对话工作台”与地图、表单、报告和图层共享当前状态。可以说“选择第二个地址”“开始体检”“取消体检”“打开第二份历史报告”“只看稀缺图层然后聚焦东南角然后导出标准GeoJSON”。最多六步的计划逐步执行，“继续”推进；收费计算与审核决定先确认，约束歧义先澄清。会话、计划及参数保存在 SQLite，刷新后恢复。逐项功能与验证范围见 [AI 融合全量验收](validation/ai-first-completion-2026-10-14.md)，早期部分实现保留在 [10月13日实施记录](validation/ai-first-implementation-2026-10-13.md)。

报告面板的“AI核验”连接设施语义审核、版本目录重算、居民文字/图片观察与人工核验、预算主动补测、原生等时圈探测、可信候选与人口台账、组合选址及角色报告。可直接询问“生成设施语义审核建议”“查看审核目录”“按审核目录重算”“查看居民报告”“覆盖优化，预算10万元，最多3家药店”。可信数据不足时显示缺项或未知；预测图层不进入正式评分，审核重算生成新报告，旧报告不变。嵌入、OCR、外部规范与费用配置见 [治理与评估说明](governance/ai-first-governance-and-evaluation.md)，原生能力和主动补测见 [空间验证说明](validation/spatial-completion-2026-10-14.md)。

左侧参数面板提供“用一句话发起体检”：输入“体检沙涌长盛花园，步行15分钟，关注买菜和买药”，点击“整理需求”。缺少地点时可以继续补充；也可以明确说“当前选点”。系统通过地图接口确认地址，多个候选需要自行选择。核对或修改步行时间、分析精度和设施类别后，点击“确认并开始快照体检”或“确认并开始真实分析”，才会启动既有体检任务。

未启用模型时显示“规则解析”，模型出错或返回不合格内容时显示降级状态。默认值会展示在预览中：15分钟、快速分析、全部七类设施。时间仅支持10、15、20分钟；未知地址不会替换成默认中心点。离线快照只支持内置沙涌长盛花园样例，其他社区需启用真实地图服务且在黄埔区支持范围内。详细行为和接口见 [自然语言体检入口说明](自然语言体检入口.md)。

模型负责提取用户需求、选择相关事实，以及选择规划查询和模拟工具，不负责评分、路线、盲区分类或模拟计算。报告解读先生成确定性的规则结果；模型只能选择绑定当前报告的事实槽位和既有建议，数值与事实文本由服务器渲染。普通解读和规划问答都拒绝模型附带的自由文本事实；模型超时、调用失败或输出不合格时自动降级到规则模板。

模型启用步骤、环境变量与密钥安全统一见 [根 README](../../README.md#六启用外部模型解读可选)，此处不重复维护配置示例。

兼容 OpenAI Chat Completions 协议的模型服务也可以直接使用 `LLM_BASE_URL` 切换。自然语言入口、报告解读与工具规划助手共享配置；修改后重启后端。API Key 不会返回浏览器，也不会写入报告。启用外部模型后，需求文本、上一轮参数、规划上下文和工具结果会发送到模型服务；整理需求本身不创建分析任务，但查询位置会调用地图地理编码接口。

### 能调用工具的规划助手

完成体检后，在右侧“可解释 AI 规划助手”输入“查一下菜市场盲区，再模拟新增一个菜市场”。模型可以依次调用设施查询、网格证据、规划候选点和新增设施模拟；工具结果返回模型继续处理，界面展示实际调用参数、成功或失败状态、数据来源和证据。成功的模拟直接联动地图及指标对比，无需再次点击运行。

可先点选地图网格，再询问该网格的依据；也可在“新增设施改善模拟”选择类别、点击“地图选点”指定位置，然后让助手模拟该点。追问会带上服务端保存的上一轮上下文，“开始新话题”清空追问关联；切换报告会隔离上下文。原报告不会被改写，假设设施不会写入主数据。

模型服务必须支持原生函数工具调用；不支持或失败时明确显示降级并保留已执行结果。未启用模型时显示“规则工具 · 模型未启用”，通过关键词选择同一组后端工具。每轮最多六次工具调用、一次模拟，整体预算九十秒。查询来自当前报告快照；真实地图模式的模拟可能消耗路线额度，离线结果仍是合成样例。接口、边界及验证说明见 [工具规划助手](工具规划助手.md)。

### 多方案比较

体检完成后，在规划助手选择“减少重点盲区”“扩大分类覆盖”或“提高综合指数”，点击“比较方案”。模型组织二至三个候选方案，后端分别基于同一原报告调用既有模拟算法并计算排名；未启用模型时规则模式也可组织报告候选方案。路线或网格数据不完整的方案不参与排名，并展示原因；点击任一方案可在地图查看已计算结果。方案独立比较，不叠加设施，也不估算建设成本、人口受益或土地可行性。详见 [多方案比较](多方案比较.md)。

### V2 报告契约兼容说明

公开分析流程仍保持 `POST /api/analyze`、`GET /api/analyze/{task_id}` 和 `GET /api/report/{task_id}`，原有 `source`、`quality`、`pois`、`zones`、`categories` 等字段继续保留。V2 报告新增以下稳定字段：

- `schema_version`、`report_id`、`task_id` 和 `completeness`；
- `calculation_mode`，记录分析档位、地图提供方模式、坐标系和步行计算方法；
- `execution`，记录具名任务阶段和执行指标；
- `data_quality`，结构化记录真实 API、缓存、本地快照、插值、降级估算和部分失败；
- `facilities`、`service_areas`、`category_scores`、`simulations` 和 `exports` 等后续功能章节。

地图能力通过统一提供方边界接入。默认离线演示使用本地快照提供方；测试可通过 `create_app(provider=...)` 注入确定性提供方，测试套件不会访问真实百度地图服务。本地快照或降级估算会明确显示“非实时数据”，不会被描述为最新真实地图测算。

### 任务与历史报告持久化

分析任务、请求参数、错误信息和完成报告保存在 SQLite。默认开发数据库位于 `backend/data/runtime/life-circle.db`，也可通过 `LIFE_CIRCLE_DATABASE_PATH` 指定；Docker Compose 使用 `analysis-data` 命名卷，因此 API 容器重建后历史报告仍可恢复。

数据库启动时按 `backend/app/storage/migrations/` 顺序迁移。每次仓储操作使用独立连接并开启外键、WAL 和忙等待；已完成报告由数据库触发器保持不可变。服务重启会识别中断任务，已成功的提供方调用检查点可续用；计费状态未决的调用先人工核对，不能自动重放。失败或中断任务满足门禁后可从原预算续算，主动取消的任务不自动恢复；另建任务重新体检仍保留。

全入口执行账本记录实际 HTTP 尝试、物理路线对、模型 token、预算与版本。报告说明提供账本、未决检查点核对和人工账单结算历史；价格或用量不足时估算费用未知，只有人工核验本次执行账单后才显示结算金额。续算新增用量使旧结算过时，更正采用追加版本。

历史接口：

- `GET /api/reports/history`：分页获取按完成时间倒序排列的报告摘要，不加载报告正文；
- `GET /api/reports/{report_id}`：按稳定报告标识打开完整报告；
- `POST /api/reports/{report_id}/rerun`：复制原请求参数创建新的任务和报告；
- 原有 `GET /api/report/{task_id}` 保持兼容。

### 步行计算缓存与可靠调用

步行坐标对结果保存在同一 SQLite 数据库的 `walking_cache` 表中，缓存键包含提供方、有方向的起终点、步行方式和规范化坐标。只有成功结果会写入缓存，并保存原始数据来源、创建时间和过期时间；过期记录不会作为有效结果复用。

手工坐标输入支持 WGS84、GCJ-02 和 BD-09。WGS84/GCJ-02 会调用百度 Geoconv V2 转换为 BD-09，再执行黄埔区范围校验和逆地理编码；离线快照不会伪造外部坐标转换，只有真实百度 Web 服务模式可用。项目内部、缓存和报告统一保存 BD-09。

真实地图模式优先使用提供方的批量步行矩阵能力；提供方不支持批量时，系统按 `WALKING_MAX_CONCURRENCY` 和 `WALKING_QPS` 执行受控并发。超时、最大重试次数、指数退避基数和缓存有效期分别由 `WALKING_TIMEOUT_SECONDS`、`WALKING_MAX_RETRIES`、`WALKING_RETRY_BASE_SECONDS` 和 `WALKING_CACHE_TTL_SECONDS` 配置。部分坐标对失败不会使整份报告失败，但报告会标记为部分结果，受影响类别不会纳入综合评分。

`GET /api/health` 和 `GET /api/map/status` 只报告真实模式是否完成配置，不主动调用百度接口，也不把“配置完成”误报为“接口已连接”。需要验证时，在界面点击“验证 Web API”或显式调用 `POST /api/map/probe`；该操作会执行一次地理编码探测并消耗真实 API 配额。探活成功只证明地理编码端点可用，POI、步行接口和浏览器底图权限仍需分别验证。

V2 报告的 `execution.metrics` 记录步行提供方调用量、真实 API 调用量、批量调用量、缓存命中/未命中/过期量、重试、限流、超时、格式错误、最终失败、降级结果和步行计算耗时；`data_quality` 同时披露缓存、限流、超时和格式错误事件。

### 技术规则与导出

- 地图 API 分为设施发现、直线距离预筛、步行路线和报告组装四个阶段。多关键词按词分别请求，以百度 `uid` 优先、再按规范化名称+坐标去重，避免一次组合查询导致召回为零。
- 设施进入分析前统一执行语义归一化：识别稳定子类，并合并同址的医疗机构主体与下属门诊，同时保留别名和原始标识供审计。详见 [V2.1 设施语义归一化](architecture/v2.1-facility-normalization.md)。
- 等时圈使用径向采样；`demo` 使用较少方向，`analysis` 增加方向和边界细化。任一采样失败都会写入数据质量事件。
- 服务区域按民生设施类别独立分类：步行超时且周边 1 公里无同类设施才是重点盲区；只满足一个条件则为稀疏区。评分包含数量、最近步行时间、空间分布三个子分，无有效数据的类别不纳入综合分。
- 规划建议引用具体类别和网格，模拟新增设施仅修改场景报告，不修改来源 POI。

#### 导出指南

完成分析后，在报告面板选择 JSON、CSV、GeoJSON（BD-09）、标准 GeoJSON（WGS84）或 PDF；也可直接调用：

```bash
curl -OJ 'http://localhost:8000/api/reports/<report_id>/exports/json'
curl -OJ 'http://localhost:8000/api/reports/<report_id>/exports/csv'
curl -OJ 'http://localhost:8000/api/reports/<report_id>/exports/geojson'
curl -OJ 'http://localhost:8000/api/reports/<report_id>/exports/geojson-wgs84'
curl -OJ 'http://localhost:8000/api/reports/<report_id>/exports/pdf'
```

调用时将 `<report_id>` 替换为已完成报告的标识。JSON 是完整报告，CSV 适合设施和评分表格，PDF 适合评审与汇报。原 GeoJSON 使用 BD-09，兼容旧调用；标准出口将几何和分析中心本地近似逆转换为 WGS84，保留孔洞并规范环方向，带转换版本、源坐标系和精度说明。原请求参数仍保留 BD-09 并单独标记，地图与正式报告不变。该转换不是官方或测绘级认证，迭代残差不是现场精度；无效或退化几何返回422，不补造可达范围。每种格式都带报告标识、参数和数据质量说明。

## 性能基线

完成报告会展示总耗时、主要阶段耗时、步行 API 调用量和缓存命中情况。可复现的本地快照与真实 API 测量命令、环境记录要求、优化结果和已知瓶颈见 [V2 性能基线文档](performance/v2-baseline.md)。后端运行后可直接执行：

```bash
python3 scripts/performance_baseline.py --runs 2
```

## V2.1 全网格基准评估

项目提供从体检报告生成人工标注模板的命令行工具。完成逐格核查后，可自动输出混淆矩阵、准确率、精确率、召回率、F1 和有效预测覆盖率。命令与指标口径见 [V2.1 全网格基准评估指南](validation/v2.1-benchmark-evaluation.md)。

```bash
python3 backend/scripts/evaluate_benchmark.py --help
```

## 参赛材料生成

在离线模式启动容器后，可生成截图、作品介绍并执行材料预检：

```bash
make contest-screenshots
make contest-brief
make contest-preflight
```

生成材料前需安装前端与后端依赖，并激活后端虚拟环境；截图采集另需脚本可用的本地 Chrome/Chromium。`contest-preflight` 区分自动失败与必须人工完成的事项；正式提交前可执行 `python3 scripts/contest_preflight.py --strict`，将真实百度复跑、真实步行路线截图、演示视频、赛事回执和远端发布门禁等人工未完成项列为阻断项。离线截图只证明产品交互，不替代真实模式证据。
