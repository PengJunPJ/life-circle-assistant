# 维护路线

本路线把代码能力、证据成熟度和授权条件分开管理。状态更新必须有链接或可复现命令，未满足前置条件的项目不得写入“已完成”宣传材料。

## 当前版本

| 项目 | 状态 | 前置条件 | 验收标准 | 风险/宣传边界 |
| --- | --- | --- | --- | --- |
| 百度主分析、离线快照与降级披露 | 已完成 | 质量门禁通过 | `make quality` 与现有报告证据可复现 | 单源结果，不代表跨源准确率 |
| 高德辅助适配器 | 已实现，默认关闭 | Key 仅存本地环境 | `make amap-probe` 可做脱敏连通性探测 | Key 不等于留存/展示许可 |
| 多源匹配纯计算模块 | 已实现，未上线 | 真实双源样本和人工标签 | 单元测试通过，运行时开关仍为 false | 不得宣称已完成多源分析 |
| 开源治理和依赖审计材料 | 初版完成 | 维护者复核链接和权限 | 文档、清单、审计命令可追溯 | 扫描不是法律意见 |

## 中期维护

- 增加 2–3 个不同路网和设施密度社区的独立核查，并分别记录来源、口径和日期。
- 为 Docker 基础镜像接入 Trivy 或 Grype CVE 扫描，并将镜像报告与发布版本绑定。
- 自动生成 Python/npm/Docker 的 SPDX 或 CycloneDX SBOM，保存脱敏 manifest 和生成工具版本。
- 将来源适配器、坐标转换、时效字段和冲突审计抽象为可替换接口。
- 定期复核百度、高德、OpenAI-compatible 服务条款和数据留存限制。

中期项目在没有独立证据前都不阻塞离线演示，但会阻塞“多源准确率”“最新真实结果”或“完整合规”之类的对外表述。
