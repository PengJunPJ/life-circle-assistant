# 开源治理

## 项目身份

- 主仓库：GitHub `PengJunPJ/life-circle-assistant`，作为参赛和发布的唯一权威仓库。
- 许可证：Apache License 2.0，见仓库根目录 `LICENSE`。
- 当前交付定位：功能型 Beta，不是规划审批或生产多租户系统。
- 默认演示：本地快照和缓存种子；真实地图调用需要用户自行配置并承担配额与条款责任。

## 变更流程

1. 通过 GitHub Issue 描述问题、背景和验收条件；安全问题走私密报告渠道。
2. 从目标分支创建短生命周期分支，提交小而可审查的变更。
3. Pull Request 必须说明测试、数据来源、隐私/授权影响和证据材料变化。
4. CODEOWNERS 评审后，GitHub Actions 的后端、前端、容器质量门禁和相关安全检查必须通过。
5. 合并后更新 `CHANGELOG.md`、发布说明和必要的证据索引。

当前未声明已启用 DCO、CLA 或强制签名提交；贡献者仍需确认拥有提交代码和材料的权利。

## 发布与回滚

版本遵循语义化版本号。`vX.Y.Z` 标签触发发布工作流，工作流会复核 VERSION、Python/npm 依赖审计和完整质量门禁，并构建带 SBOM/provenance 的 GHCR 镜像。正式发布还需人工检查 GitHub Actions 结果、许可证/服务条款材料和 `.env`/数据库未进入附件。

发现严重问题时回滚到最近一个已验证标签，并在变更日志和发布说明中记录影响。高德辅助验证失败不得阻断百度主分析，也不得被包装为多源准确率。

## 数据与外部服务责任

百度是当前正式分析主来源。高德适配器仅为默认关闭的辅助观察源；Key 只证明调用凭证，不证明数据留存或公开展示许可。没有书面许可和人工双源标签前，不提交原始高德 POI，不生成多源准确率结论。

治理材料中的扫描、审计和 SBOM 是工程证据，不是法律意见；未确认许可证、镜像许可或外部服务条款的项目必须标记 `needs-review`。
