# 自然语言体检入口

左侧参数面板新增对话入口，支持描述需求、补充信息、确认地图位置、编辑参数和启动原有体检流程。现有手工表单继续可用。

## 使用步骤

1. 输入“体检红山街道海韵东路，步行15分钟，关注买菜和买药”，点击“整理需求”。也可点击“试试当前选点”填入示例后发送。
2. 缺少位置时继续输入“地址是红山街道海韵东路”，或明确说“当前选点”。补充消息保留上一轮参数；“加上公园”“不要药店”“改为20分钟”等表达可修改需求。
3. 地图服务返回多个候选时必须选择位置；无候选或超出支持范围时不能启动。地址输入框允许手动修改，修改后需要重新点击“确认位置”。
4. 检查预览中的地址及百度坐标、步行时间、分析精度和关注设施。可以直接修改下拉框及复选框。
5. 点击“确认并开始快照体检”或“确认并开始真实分析”。参数会同步到既有表单，并通过原有分析任务生成报告。

不支持的时间不会静默换成可用时间；请选10、15或20分钟。未发送的修改、整理中的请求、未确认的位置以及空设施列表都会阻止确认启动。使用“当前选点”后若地图位置改变，需要重新发送确认当前选点。

对话草稿出现后，原手工表单的启动按钮会暂时隐藏，避免误用旧表单参数。点击“重新开始”清空对话草稿后，手工启动按钮恢复。

## 模型配置与降级

与报告解读共享应用目录 `.env` 中的 `LLM_ENABLED`、`LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 等配置。启用后重启后端；Docker 用户需要重新构建前端并重建后端容器以使用新入口。密钥仅在后端使用。

| 页面状态 | 实际行为 |
| --- | --- |
| 模型解析 | 后端模型返回经过结构校验的参数；展示模型名称 |
| 规则解析 · 模型未启用 | 使用本地中文规则提取常见地址后缀、时间及设施关键词 |
| 规则解析 · 模型不可用或结果未通过校验 | 模型请求失败、枚举不合法、生成坐标或编造地点等情况下使用规则降级 |

规则解析能力有限，复杂措辞或难以识别的地名建议使用“地址是……”补充，或直接编辑预览。默认参数是15分钟、快速分析、全部七类设施，预览中会标出仍采用默认值的字段。

启用模型时，需求文本和上一轮结构化参数会发送给所配置的模型服务。对话最多展示最近八条消息，保存在当前组件内存中，刷新页面后清空；分析任务与报告仍按既有 SQLite 机制保存。

## 技术流程

`POST /api/analysis/intent` 接收 `message`（1～1000字，不能全为空白）与可选 `previous` 参数草稿，返回 `draft`、`parser`、`model`、`missing_fields` 和追问/确认提示。草稿只有地址文本、是否使用当前选点、时间、精度、设施类别和默认值标记，不包含坐标或测算结果。

模型只返回本轮修改字段，后端校验枚举、地址必须逐字来自本轮消息、使用当前选点必须来自明确表达；机器可识别的时间表达优先，避免模型擅自将30分钟改成20分钟。失败时返回可核对的规则草稿，不返回异常中的凭证或服务细节。

前端随后使用现有 `GET /api/geocode` 获取地址候选，并遵守既有黄埔区支持范围与快照限制。多个候选由用户选择。当前选点必须已经通过既有位置确认流程。用户确认后才调用原有 `POST /api/analyze`，沿用等时圈、设施覆盖、盲区识别和报告流程。

“整理需求”本身不创建分析任务，也不计算评分。位置查询在真实地图模式下会消耗地理编码配额；确认启动会执行原有地图测算。离线样例结果仍是非实时数据。

## 验证与范围

后端测试覆盖参数提取、连续修改、缺失地点、不支持时间、错误模型输出、网络异常降级以及解析后才显式启动分析。前端测试覆盖参数编辑、多候选、查询错误、当前选点变化、未发送修改和确认事件到既有分析流程的连接。

本次仅实现自然语言发起体检，没有新增模型自主调用规划工具、多方案比较或自动 POI 清洗。外部模型真实连通性、真实地图数据有效性及现场步行感受需要分别验证，离线测试不能替代这些证据。
